# Plan 04-01 — ROI 协商协议改造（Phase 4 全部模块的硬前置）

## Goal

把 `PixelPipe.processRec` 从「恒等 ROI assert」改造成 **Darktable 式两趟真协商**（D-G5 / ROADMAP SC#4 / 04-CONTEXT 的本阶段架构验收核心）。这是 `processRec` 的一次**结构性改造，不是新模块**：

1. **前向趟**（dt `dt_dev_pixelpipe_get_dimensions`，`pixelpipe_hb.c:3368-3405` 直译）：`run()` 内、`processRec` 之前，按 v50 序逐件走 `modifyROIOut`，产出每件的 buf_in/level ROI 与管线最终输出尺寸。
2. **后向趟**（`pixelpipe_hb.c:2085-2096` 模式）：递归 miss closure 内调 `modifyROIIn` 求输入 ROI，以协商 ROI 递归上游；替换 `PixelPipe.swift:549-553` / `:586-590` 的 "pass-through-era ROI identity violated" 恒等 assert。
3. **输入平面子域渲染**：协商传导到 base case 时按带偏移 ROI 渲染子域（CI lazy cropped），crop 之后**下游平面按裁切尺寸原生分配**（04-RESEARCH §1.2 对 D-G2「不实际裁切内存」的正解读——不是 buffer 保持全幅，而是不需要先全幅再拷窗）。

**不改缓存键结构**：`PipeCacheKey.roi` 字段（`PipeCacheKey.swift:37`）Phase 2 已预留、本阶段首次实际生效；`levelHash` 只折 enabled 件 paramsHash、与 ROI 无关——**ROI 轴与 params 轴正交**，两级失效语义都不破坏。

**顺序纪律**：本 plan **all-green 前，04-02..04-05 一律不得动工**（8 个模块全部消费本协议）；测试先行——先在现码上加固 ROI 恒等用例，再动实现。

## Must-haves

- `ModuleBoxing` 增补 `modifyROIOutErased` / `modifyROIInErased` 两个 erased 转发（机械活，`ModuleBox.swift:61-75` erased 模式照抄）
- 前向预计算：`levelROI[i]`（每件 OUTPUT roi = dt buf_out）+ `bufInROI[i]`（每件 buf_in）两组数组；禁用件直通（dt `:3378-3384` 同语义）；`dscIn` 盖章从统一 pieceGeometry 改为 per-level
- 真协商：miss closure 内 `modifyROIIn` → 以 roiIn 递归上游 → 新 assert「协商后上游平面尺寸 == roiIn」；disabled 直通分支 roiOut 直传
- 输入平面子域渲染变体：`ciImage.cropped(to:)` + 按 roiOut 尺寸渲（替代 `:496-501` 只按 longEdge 全幅）
- `RenderPipeline.process` 增 `roiHint: ROI? = nil`（nil = 全幅；Phase 4 仅测试/探针面，UI zoom-ROI 另议）
- **SC#4 四断言 harness**（04-RESEARCH §7）：①crop 前向收缩树内断言 ②sharpen 后向外扩内存断言 ③禁用穿越恒等 ④拖动 N 次缓存旧键保留
- executeTiled 的 readRect「输入平面 == roiOut 尺寸」假设对齐协商后 roiIn 尺寸（`PixelPipe.swift:278-282`）
