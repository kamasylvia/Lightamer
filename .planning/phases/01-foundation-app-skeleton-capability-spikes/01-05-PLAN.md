# Plan 05 — Spike A (CIRAW 9 boundary) + Spike B (100MP perf vertebra)

> **`autonomous: false`** — spikes involve visual judgment (golden-sample comparison, FPS reading) and decision-making that may reshape Phase 3+ scope. The executor runs the methodology, records measurements, and proposes a decision; the user/approver signs off on the v1 iop-scope implications. See the spike decision criteria below — they can escalate to a Phase 3+ scope change.

## Goal

Run the two research-flagged spikes whose outcomes determine v1 iop scope and validate the architectural vertebra (Phase 1 success criterion #4):
1. **Spike A — CIRAW 9 capability boundary:** For each target camera family (Bayer pro, Bayer consumer, X-Trans, Quad-Bayer, DNG), determine which demosaic/denoise/lens features RAW 9 covers natively vs. which need a Metal port. **Outcome decides whether the per-method demosaic menu (Darktable's PPG/RCD/AMaZE/VNG/Markestejn) is a v1 hard requirement or can defer to Apple-default.** This can expand Phase 3 scope materially (a Markesteijn X-Trans port is ~700 lines of MSL).
2. **Spike B — 100MP Metal performance vertebra:** Confirm 60fps feasibility on a GFX100S RAF (the headline torture image) at the Phase 1 display path, validate the D-32 hard budgets (decode ≤2s, display ≤500ms, steady-state memory ≤4GB, drag ≤16ms), and decide whether the D-20 "no tiling in Phase 1" decision holds or tiling becomes a Phase 2 hard requirement.

Both spikes run on independent branches per D-06, with minimal self-contained verification apps that do NOT depend on the main app's `MetalContext`/`RAWDecoder` (RESEARCH §8 gotcha — spikes are throwaway but useful patterns may be back-ported). Reports + golden samples are checked in.

## Tracer vertebra mapping

These spikes do not extend the vertebra; they **validate** it. Spike B in particular confirms that the Plan 01-04 vertebra (open-RAW→display) survives the 100MP torture case — the Phase 1 success criterion #4. Spike A's outcome is a planning input for Phase 3 (it determines whether the demosaic menu port is v1 scope).

## Must-haves (goal-backward verification)

- [ ] Spike A app exists on branch `spike/ciraw9-boundary`, launches, decodes a sample set side-by-side (RAW 8 vs RAW 9), logs `supportedDecoderVersions` per file.
- [ ] Spike A report (`spike-report-A.md`) contains a per-camera-row table: sensor family | RAW 9 supported? | demosaic quality (1-5) | denoise quality (1-5) | lens correction coverage | decode time | memory | notes.
- [ ] Spike A report contains a decision: per camera family, is Apple-default demosaic acceptable for v1, or does the per-method menu become a v1 hard requirement?
- [ ] Spike A golden samples (100% crops of torture regions: deep shadow, edge detail, X-Trans maze) committed under `samples/`.
- [ ] Spike B app exists on branch `spike/100mp-perf`, launches, opens a GFX100S RAF, decodes, blits to MTKView, with `os.signpost` per frame + FPS counter.
- [ ] Spike B report (`spike-report-B.md`) contains a per-resolution-row table: image | MP | decode time (RAW 8/9) | memory peak | blit time | drag fps | notes.
- [ ] Spike B report contains a decision: does D-20 (no tiling in Phase 1) hold, or does tiling become a Phase 2 hard requirement? Identify the MP threshold above which tiling is mandatory.
- [ ] Both spikes' measurement methodology uses `os.signpost` (D-31) and Instruments (Metal System Trace + Allocations).
- [ ] Both spike branches remain isolated from `main` (D-06).

## Reversibility gates

- **D-20 (no tiling in Phase 1) — REVERSIBLE, but the spike can overturn it.** Spike B is the gate: if memory >4GB or decode >2s on 100MP, D-20 is overturned and tiling becomes Phase 2 scope. The spike report records the decision; if overturned, flag it for the Phase 2 planner.
- No other one-way decisions — spikes are research, not architecture commits.

## Task 01-05-04 — Spike B: run 100MP perf measurement, write report, decide on D-20 (tiling)

**action:**
1. Assemble sample files:
   - **GFX100S RAF** (~11650×8738, ~116MP, the headline torture image). **Sample source:** Obtain the GFX100S RAF sample from raw.pixls.us (community RAW sample archive) or DPReview studio scene samples. Cite the source URL in the spike report.

2. For each file, run SpikeB and measure (per RESEARCH §8):
   - **Decode time** (RAW 8 vs RAW 9) — `os.signpost` `"decode"` interval, cold and warm.
   - **Memory peak** — Instruments Allocations during full decode. **Specifically test:** does a single 100MP `RGBA32Float` plane (~1.6GB) allocate successfully? Does the lazy `CIImage` chain blow up (CIRAW-4)? Confirm `cacheIntermediates: false` keeps memory bounded.
   - **Blit time** — `CIContext.render(_:to:)` into `MTLTexture(.rgba32Float)`, `os.signpost` `"blit"` interval.
   - **Drag frame time** — while scrolling/panning, measure per-frame `"frame"` interval; compute fps. Target: ≤16ms (60fps) at viewport resolution.
   - **GPU working set** — `device.recommendedMaxWorkingSetSize`; confirm the 1.6GB plane is under budget.
3. Write `.planning/spikes/spike-b-100mp-perf/spike-report-B.md`:
   - **Per-resolution-row table:** `image | MP | decode time (RAW 8 / RAW 9, cold/warm) | memory peak | blit time | drag fps (viewport-res) | GPU working set | notes`.
   - **Decision: does D-20 (no tiling in Phase 1) hold?** Apply RESEARCH §8 criteria:
     - **Pass** (D-20 holds): decode <2s, display <500ms, memory <4GB, drag 60fps → tiling deferred to Phase 2.
     - **Fail** (D-20 overturned): memory >4GB OR decode >2s → tiling becomes Phase 2 hard requirement (escalates Phase 2 scope — flag explicitly).
     - **Partial pass**: decode >2s but display <500ms after warm cache → acceptable (decode is one-shot; cache makes subsequent views fast). Document the trade-off.
   - **MP threshold for tiling:** identify the approximate MP above which tiling becomes mandatory (e.g. ">80MP?" — based on the measurements).
   - **CIRAW-4 confirmation:** explicitly state whether `cacheIntermediates: false` kept the lazy CIImage chain bounded; if not, this is a Phase 2 finding.
   - **Implications for Phase 2:** if D-20 is overturned, the Phase 2 pixelpipe plan MUST include tiling — call this out.
4. Commit the report on `spike/100mp-perf`. Do NOT merge until user reviews the decision.
