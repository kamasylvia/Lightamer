# Plan 03 — MetalContext (Core) + PassThrough.metal (IOP) + EditorMTKView (app): completes the open→display tracer

## Goal

Land the render half of the Phase 1 vertebra, spanning all three implementation modules: (1) **`MetalContext`** (`public actor` in `LightamerCore/Sources/Metal/`) — the Metal dispatch framework with default device, single `MTLCommandQueue` (D-15), lazy+memory PSO cache (D-16), function-constants (D-17), `throws` errors (D-18), two-layer dispatch API (D-19); (2) **`CIContextPool`** (`internal actor` in Core/Metal) — the CIImage→MTLTexture bridge using `WorkingSpace.colorSpace` (linear Rec2020, FOUND-02); (3) **`PassThrough.metal` + `Passthrough.swift`** in `LightamerIOP/Sources/` — the trivial pass-through kernel proving the MetalContext dispatch end-to-end (success criterion #2); (4) **`EditorMTKView`** (`internal NSViewRepresentable` in `App/Sources/Lightamer/UI/`) — the SwiftUI↔MetalKit bridge that consumes `EditorState.image` and blits the decoded `CIImage` to the screen via the Core render path.

This plan completes success criteria #1, #2, and #3 together: open a CR3/NEF/ARW RAW → `RAWDecoder` (Plan 02) produces a `DecodedImage` → `CIContextPool` renders `ciImage` to an `MTLTexture` → `MetalContext` blits it through a render pipeline → `EditorMTKView` displays it. The result is a decoded RAW visible in the editor viewport with no adjustments and no zoom/pan (D-13).

## Tracer vertebra mapping

Wave 1 plan #3. Completes the vertebra started by Plans 01 (shell) + 02 (decode). After this plan: File → Open → `EditorState.load` → `RAWDecoder.decode` → `DecodedImage` → `EditorMTKView` reacts to `editorState.image` → `CIContextPool.renderToTexture` → `MetalContext` blit → pixels on screen.

## Reversibility gates (one-way / costly decisions)

- **D-16 (PSO cache = lazy + memory) — COSTLY.** The cache shape (`PSOKey` → `MTLComputePipelineState`) is the dispatch hot path; changing the eviction policy or key shape later affects every iop. A `checkpoint:decision` task precedes writing `MetalContext.swift`.
- **D-19 (two-layer dispatch API) — COSTLY.** The `dispatch2D` / `dispatch2DTexture` / `makeEncoder` signatures are the contract every iop (Phase 3+) calls through. Locked by checkpoint.
- **D-14/D-15 (default device + single queue) — REVERSIBLE** but the `commandQueue` is exposed `private(set)` as a seam for the Phase 11 low-priority export queue (RESEARCH §3 gotcha).

**action:** Create two files in `LightamerIOP/Sources/`:
1. `Passthrough.metal` — the trivial pass-through kernel per RESEARCH §3:
   ```metal
   #include <metal_stdlib>
   using namespace metal;
   constant bool useSrgbGamma [[function_constant(0)]];
   constant float exposureEV  [[function_constant(1)]];
   kernel void pass_through(
       texture2d<float, access::read>    in     [[texture(0)]],
       texture2d<float, access::write>   out    [[texture(1)]],
       uint2 gid                                 [[thread_position_in_grid]]) {
       float4 c = in.read(gid);
       if (useSrgbGamma) { c = float4(pow(c.rgb, float3(1.0/2.2)), c.a); }
       c.rgb *= pow(2.0, exposureEV);
       out.write(c, gid);
   }
   ```
   (L006: use `float`/`float3`, not `half`, in shadow-sensitive math.) This compiles into `LightamerIOP`'s `default.metallib` via Xcode's default Metal build rule.
