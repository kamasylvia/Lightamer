# Plan 03 — MetalContext + EditorMTKView (completes the tracer: "open a RAW → see it on screen")

## Goal

Deliver the Metal dispatch framework and the SwiftUI↔Metal viewport bridge that completes the Phase 1 tracer vertebra. Specifically:
1. `MetalContext` actor (D-14..D-19): default device, single `MTLCommandQueue`, lazy + memory-cached PSO with function-constants specialization, throws-typed errors, two-layer dispatch API (`dispatch2D` high-level + `makeEncoder` low-level). This is the dispatch entry every Phase 2+ iop uses.
2. `CIContextPool` actor: one `CIContext` per `MTLDevice`, working color space = linear Rec2020 (FOUND-02), `cacheIntermediates: false` (CIRAW-4 pitfall). Renders `RAWDecoder`'s `CIImage` to an `.rgba32Float` `MTLTexture`.
3. `Sources/IOP/PassThrough.metal`: the trivial compute kernel (success criterion #2 — buffer in → bit-exact buffer out) plus a function-constants-specialized variant proving D-17.
4. `EditorMTKView: NSViewRepresentable` (D-13, FOUND-05): wraps `MTKView`, owns the `Coordinator` per-frame render loop, blits the source `MTLTexture` to the drawable. Phase 1 scope is display-only (no zoom/pan — D-13 defers).
5. Wire `EditorState.image` → `CIContextPool.renderToTexture` → `EditorMTKView.sourceTexture` so that opening a RAW (Plan 02) displays the decoded pixels in the center column. **This task completes the open-RAW→display vertebra.**

## Tracer vertebra mapping

This plan is the display half. After task 01-03-05, the end-to-end vertebra is live: File → Open (Plan 02) → `EditorState.load` → `RAWDecoder.decode` → `DecodedImage.ciImage` → `CIContextPool.renderToTexture` → `EditorMTKView.sourceTexture` → `Coordinator.draw` → pixels on screen. The Phase 1 success criterion #1 ("app launches on macOS 27 and opens a CR3/NEF/ARW via CIRAW 9, displaying the decoded image in the MTKView viewport") is satisfied here.

## Must-haves (goal-backward verification)

- [ ] `MetalContext` initializes: `MTLCreateSystemDefaultDevice()` non-nil, `commandQueue` non-nil, `library = device.makeDefaultLibrary(bundle: .main)` non-nil (loads `default.metallib`).
- [ ] The pass-through compute kernel executes end-to-end: an input `MTLBuffer` of known float32 values → output `MTLBuffer` bit-identical (success criterion #2). This is the FOUND-06 proof.
- [ ] Function-constants specialization works: a `[[function_constant(0)]] bool` flag produces two distinct PSOs in the cache (D-17 proof).
- [ ] `CIContextPool.renderToTexture(_:ciImage)` produces an `.rgba32Float` `MTLTexture` matching the CIImage extent (FOUND-02).
- [ ] `EditorMTKView` displays the decoded RAW in the center column on File → Open (FOUND-05, success criterion #1).
- [ ] `MTKView.isPaused = true` when no image, `enableSetNeedsDisplay = true` (avoid 60fps re-render storms on a static image — UI-1 pitfall).
- [ ] Opening a 100MP image does not crash (jetsam); the full perf validation is Spike B (Plan 05) — Plan 03 just confirms it renders.
- [ ] All Metal errors flow through `AppError.metalPSOFailed` / `.metalDeviceUnavailable` (D-25).

## Reversibility gates

- **D-16 (PSO cache strategy: lazy + memory) — COSTLY.** The PSO cache is the MetalContext core; changing it affects every iop call path. A `checkpoint:decision` precedes the implementing task.
- **D-19 (two-layer dispatch API: `dispatch2D` + `makeEncoder`) — COSTLY.** The dispatch API shape is the contract every iop codes against. Same checkpoint as D-16.

## Task 01-03-01 — checkpoint:decision (D-14..D-19 MetalContext design)

**kind:** checkpoint:decision
**read_first:**
- `.planning/phases/01-foundation-app-skeleton-capability-spikes/01-CONTEXT.md` — D-14 (default device), D-15 (single queue), D-16 (lazy + memory PSO), D-17 (function-constants), D-18 (throws), D-19 (two-layer dispatch), D-20 (no tiling in Phase 1)
- `.planning/phases/01-foundation-app-skeleton-capability-spikes/01-RESEARCH.md` — §3 (full MetalContext sketch: PSOKey, pipelineState cache, functionNamed specialization, dispatch2D buffer + texture overloads, makeEncoder, makeConstants helper, MTLFunctionConstantValues.fingerprint), gotchas (makeFunction constantValues requires ALL constants; single queue seam for Phase 11; storage mode .shared on Apple Silicon UMA)
- `.planning/phases/01-foundation-app-skeleton-capability-spikes/01-VALIDATION.md` — Per-Task row 01-03-01 (pass-through bit-exact)
- `LESSONS.md` — L006 (no half in shadow-sensitive paths; `.rgba32Float` everywhere)

**decision:** Lock the MetalContext contract before writing `MetalContext.swift`:
1. **D-14:** `MTLCreateSystemDefaultDevice()` (Apple Silicon UMA). Single GPU, no multi-device selection.
2. **D-15:** Single `MTLCommandQueue` (Phase 1 display-only, no contention). Keep `commandQueue` as `private(set)` so the Phase 11 low-priority export queue seam is just `device.makeCommandQueue()` again.
3. **D-16:** PSO cache = lazy + in-memory `[PSOKey: MTLComputePipelineState]` dictionary. No disk serialization (Metal doesn't support it; `.metallib` is already in the bundle). PSOKey = `(functionName, constantsFingerprint)`. Costly to change.
4. **D-17:** Function-constants via `[[function_constant(N)]]` in `.metal` + `MTLFunctionConstantValues` + `library.makeFunction(name:constantValues:)` on the Swift side. The cache returns a distinct PSO per `(name, constants)` pair.
5. **D-18:** All Metal failures throw (typed `MetalError` bridged to `AppError.metalPSOFailed` / `.metalDeviceUnavailable`).
6. **D-19:** Two-layer API: high-level `dispatch2D(functionName, input, output, width, height, threadgroupSize, constants, configure)` for simple iops; low-level `makeEncoder(functionName, constants) -> (MTLCommandBuffer, MTLComputeCommandEncoder, MTLComputePipelineState)` for fine-grained control. Both buffer and texture overloads of `dispatch2D`. Costly to change.
7. **D-20:** No tiling in Phase 1. Spike B (Plan 05) validates whether 100MP fits in 16GB; tiling framework is Phase 2 if needed.
8. **Storage mode (RESEARCH §3 gotcha):** Apple Silicon UMA → `.shared` everywhere is correct and simplest. Use `.private` for large GPU-only intermediates (the rendered texture), staged through the CIContext render (which handles the staging internally).

**acceptance_criteria:**
- Checkpoint task marked done before 01-03-02.
- The eight locked decisions above affirmed (CONTEXT.md records D-14..D-20 user sign-off).

**action:** No file change. Gate before implementation.
