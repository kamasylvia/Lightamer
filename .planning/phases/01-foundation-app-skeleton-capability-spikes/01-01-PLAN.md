# Plan 01 — Tuist multi-target project + SwiftUI shell + isolated state (tracer vertebra: "tuist generate → app launches → empty shell")

## Goal

Stand up the greenfield macOS 27 app as **five Tuist targets** whose boundaries are compiler-enforced via Swift access control (`public` = cross-module API surface, `internal` = module-private). The `Project.swift` manifest declares the directed acyclic dependency graph (DAG): `LightamerCore` (framework, no Lightamer deps) ← `LightamerIOP` (framework, deps Core) ← `Lightamer` (app, deps Core + IOP); plus `LightamerTests` (deps Core + IOP) and `LightamerUITests` (deps app). This is the leading tracer vertebra — `tuist generate` produces a `.xcodeproj`, the app launches, and the three-column `NavigationSplitView` shell renders empty with forced dark mode.

The plan also lands three foundational pieces every later plan depends on: (1) `WorkingSpace` + `AppError` as `public` types in `LightamerCore/Sources/Foundation/` (the cross-module value types); (2) the **four isolated `@Observable` state objects** (D-03b — `SessionState`, `EditorState`, `ExportState`, `InspectorState`, each `@MainActor`, no god-object, each owning its own subsystem's state); (3) the full UI chrome per UI-SPEC (three-column shell, empty-state card, top toolbar, menu bar, status bar, neutral-gray color tokens, String Catalog). Plans 02-04 plug `RAWDecoder`, `MetalContext`, `EditorMTKView`, and the pixelpipe skeleton into this shell.

## Tracer vertebra mapping

Wave 1 plan #1. Produces the *shell* half of the Phase 1 vertebra ("open a RAW and see it on screen"): an app that launches, shows the three-column chrome with an empty editor area, holds four isolated state objects, and is ready to receive a `RAWDecoder` (Plan 02) + `EditorMTKView` (Plan 03). The vertebra is completed by Plan 03's task that wires `EditorState.load(url:)` → decoded texture → `EditorMTKView` in the center column.

## Must-haves (goal-backward verification)

- [ ] `tuist generate` exits 0 and produces `Lightamer.xcodeproj` with exactly five targets: `LightamerCore` (framework), `LightamerIOP` (framework), `Lightamer` (app), `LightamerTests` (unit tests), `LightamerUITests` (UI tests).
- [ ] `tuist graph` shows the acyclic DAG: `LightamerCore ← LightamerIOP ← Lightamer`; `LightamerTests → {Core, IOP}`; `LightamerUITests → Lightamer`. No cycles.
- [ ] `xcodebuild build -project Lightamer.xcodeproj -scheme Lightamer -destination 'platform=macOS'` exits 0 on the macOS 27 SDK.
- [ ] `Lightamer.app` launches without crashing; the three columns (sidebar / editor area / inspector) are visible.
- [ ] Dark mode is forced regardless of the system appearance setting (D-10).
- [ ] The empty-state prompt is shown in the editor area when no image is loaded (D-11); copy comes from `Resources/Localizable.xcstrings` keyed by string ID (not hardcoded Chinese — UI-SPEC reconciliation note).
- [ ] Bundle ID is exactly `com.kamasylvia.lightamer` on the app target (D-05, one-way).

- [ ] `.xcodeproj` is NOT committed; `Project.swift` is the source of truth (Tuist convention).
- [ ] A deliberate `internal` symbol in `LightamerCore` is NOT visible to the app target (compiler-enforced boundary — `import LightamerCore` from the app only resolves `public` symbols).

## Reversibility gates (one-way / costly decisions)

- **D-02 (multi-target + Tuist) — ONE-WAY.** The module split is structural; once `public` types in Core are consumed by IOP/app, merging modules back is a migration. A `checkpoint:decision` task precedes writing `Project.swift`.
- **D-05 (Bundle ID `com.kamasylvia.lightamer`) — ONE-WAY.** Set once in `Project.swift`; immutable after first signed build. Locked in the same checkpoint as D-02.
- **D-07 (three-column `NavigationSplitView`) — COSTLY.** The three-column shell is the SwiftUI skeleton; changing it ripples through every child view. Locked by checkpoint before `ContentView` is written.
- **D-25 (`AppError` typed enum, public in Core) — COSTLY (cross-module contract).** The error type is the contract every layer throws through; changing it rewrites every catch site across modules. Locked by checkpoint before `AppError.swift` is written.
- **D-33 (Swift Concurrency / Swift 6 strict concurrency) — ONE-WAY (project-wide).** `SWIFT_STRICT_CONCURRENCY: complete` in `Project.swift`; permeates all later code. Locked in the D-02 checkpoint.
- **D-35 (`@Observable` macro + D-03b state isolation) — COSTLY.** Replaces `ObservableObject`; reverting means rewriting every `@State`/`@Environment` owner, and the four-object isolation boundary is a view-dependency contract. Locked by checkpoint before the four state objects are written.
