# Plan 02-03 — Multi-resolution pipes + scale-at-entry + preview bucket ladder + PipeCoordinator

## Goal

Instantiate the FOUND-04 multi-resolution architecture (SC#4's pipe half): four pipe kinds sharing one module chain, one cache, one history feed — differentiated by `PipeResolution` and lifecycle (research §2.1 table):

| Pipe | Resolution | Lifecycle | Failure mode guarded against |
|---|---|---|---|
| PREVIEW | `min(drawableSize×2, 2560)` long edge, quantized to the 360px ladder (D-C3) | created on load, always-current; params change → re-render | window jitter → render storm |
| THUMBNAIL | 360px fixed | lazy: params change marks dirty, re-renders on next fetch (Phase 9 consumes) | eager re-render waste |
| FULL | scale 1.0 full extent | on-demand only, short-lived (1.55GB@100MP input plane evicted after use); NEVER auto-renders on param change | plane multiplication vs 4GB budget (spike-b) |
| EXPORT | target size | reserved stub this phase (Phase 11); `fatalError`-free placeholder API | — |

**Scale is applied at pipe entry** (Darktable `pixelpipe_hb.c:1930-1999` mirror): the input plane is rendered from the decoded `CIImage` directly at the target long edge — never render 100MP then downscale. Modules stay scale-blind in the pass-through era (`modifyROIOut/In` hooks exist but stay identity; ROI negotiation is Phase 4's acceptance).

The app gains **`PipeCoordinator`** (D-03b isolation: a new `@Observable @MainActor` object owned alongside `EditorState`): it owns the per-image pipe instances, translates *what changed* (params/display/drawable) into *which pipe re-renders*, and pushes `displayTexture`. It is also where 02-05 (history changes) and 02-06 (clearCaches triggers) plug in — the plan leaves those two seams as documented extension points.

Zoom/pan ROI interaction stays out (Phase 4) — FULL exists as a callable scaffold verified from tests, per research Open Question #4.

## Tracer vertebra mapping

Wave 3. After 02-02 one pipe runs modules with cache. After 02-03 the pipe exists as a *family*: open an image → PREVIEW pipe renders at the quantized bucket; resize the window across a bucket boundary → exactly one re-render (signpost-visible); within a bucket → zero re-renders; a FULL run is only reachable explicitly.

**action:**
1. Create `LightamerCore/Sources/Pipe/PreviewBucket.swift`:
```swift
/// D-C3 quantization: PREVIEW long edge = min(drawable×2, 2560) snapped to
/// the ladder. Same-bucket resize → no re-render (jitter guard).
public enum PreviewBucket {
    public static let cap: Int = 2560
    public static let ladder: [Int] = [2560, 2200, 1840, 1480, 1120, 760, 360]
    public static func longEdge(forDrawable drawableLongEdge: Int, pixelScale: CGFloat = 2.0) -> Int
}
```
   Logic: `target = min(Int((CGFloat(drawableLongEdge) * pixelScale).rounded()), cap)`; snap down to the largest ladder value ≤ target (below 360 → 360). Header documents the 5K/6K soft-display note (Risk #4).
2. `Tests/LightamerTests/PreviewBucketTests.swift`: boundary table — `1280→(×2)2560→2560`; `1279→2558→2200`; `920→1840→1840`; `740→1480→1480`; `560→1120→1120`; `380→760→760`; `180→360→360`; `100→200→360`; zero/negative drawable → 360 (defensive). `pixelScale` override honored.

**acceptance_criteria:**
- Pure function (no Metal/MachineState dependencies); all listed boundaries asserted green.
- `xcodebuild test -only-testing:LightamerTests/PreviewBucketTests` green.
