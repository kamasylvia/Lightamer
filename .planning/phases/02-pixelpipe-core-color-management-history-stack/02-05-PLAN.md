# Plan 02-05 — History stack: identity tuple, undo/redo/jump, history hash, tiling scaffolding

## Goal

Port Darktable's history model (`develop.h:34-49` identity tuple + `history.c:1571-1665` hashing) to the Swift side — the non-destructive core (HIST-01/HIST-02) and the drift-detection primitive (HIST-04):

1. **`ModuleInstance`** — the persisted identity+params record: `(id: UUID, opName, multiPriority, multiName, iopOrder, version, enabled, paramsData: Data, paramsHash: UInt64)`. UUID identity (NDE-1: masks/history reference instances by UUID, never ordinal — the ROADMAP Phase 2 note makes this the load-bearing choice for Phase 6). `Codable` (sidecar payload, 02-06), `Sendable`, with typed `params<M>(of:)` access. This is deliberately a plain record, NOT a module — the runtime `ModuleBox` (02-02) is manufactured from it via `ModuleRegistry` (02-04).
2. **`HistoryStack`** — ordered items + `position` pointer (−1 = pristine, Darktable `history_end` analog): `commit` (truncate after position + append — D-H1 drag-end granularity lands here), `undo`/`redo`/`jump(to:)` (HIST-02), `effectiveInstances()` — the `GROUP BY (opName, multiPriority) MAX(position)` dedup, v50-sorted (`history.c:1600-1607` direct translation). **Design decision (research §4.1): `HistoryItem` inlines a full `ModuleInstance` snapshot** (not just an instanceID reference) so undo/jump restores *params as they were* and `effectiveInstances()` stays a pure function; this maps 1:1 onto the sidecar's `items[]`.
3. **`HistoryHash`** — FNV-1a 64 over effective (enabled) instances in v50 order + `decodeParamsHash` (HIST-04/D-H4; the cache-key atom shared with 02-02). Drift *detection* against sidecars lands in 02-06; the hash itself is defined and frozen here.
4. **D-H1 drag-end API**: `PipeCoordinator.beginContinuousEdit()` → live param changes drive PREVIEW re-renders WITHOUT history commits → `commitContinuousEdit(label:)` emits exactly one `HistoryItem`. Phase 2 has no sliders; the API is exercised by tests and is the shape Phase 3's first slider consumes.
5. **`TilingPlan` scaffolding (D-20/SC#4 tail)** — pure geometry: given plane dimensions + a per-tile budget, produce the tile grid (origin/size list + overlap policy placeholder). NOT wired into `processRec` (spike-b keeps 100MP within budget at pipe level; tiling becomes load-bearing in Phase 5 denoise). A tested stub that Phase 5 fills without redesign.
6. **Coordinator integration**: history changes now drive pipes — `paramsDidChange` is replaced by `historyDidChange` (re-materialize boxes from `effectiveInstances()` via the registry → PREVIEW re-render, THUMBNAIL dirty). EditorState owns the `HistoryStack` (D-03b: "当前编辑的图像 + 图层栈 + history" — history lives in EditorState; the coordinator consumes it).

Sidecar persistence (HIST-03) is Plan 02-06 — this plan defines everything that gets persisted.

## Tracer vertebra mapping

Wave 3, parallel-friendly with 02-04 (weak coupling: only shares `ModuleRegistry` shapes). After 02-05: an edit is a history entry; undo/redo/jump re-renders through the cached pipe (upstream hits — SC#2's undo leg end-to-end); the history hash is stable across process restarts (test proves it with fixed vectors, not process-local `Hasher`).

## Must-haves (goal-backward verification)

- [ ] `ModuleInstance` is `public struct`, `Codable & Sendable & Equatable`, with the nine fields above; `paramsHash` is derivable (`StableHash.hash(paramsData)`) and stored; typed `params<M: IOPModule>(of: M.Type) throws -> M.Params` + `mutating setParams`.
- [ ] `HistoryStack` is `public struct`, `Codable & Sendable`: `items: [HistoryItem]` (D-H2: no cap), `position: Int` (−1 pristine), `commit(_:)/undo()/redo()/jump(to:)/effectiveInstances()`; `commit` truncates forward history.
- [ ] `HistoryItem` is `public struct`, `Codable & Sendable, Identifiable`: `id: UUID`, `snapshot: ModuleInstance` (inline), `label: String`, `timestamp: Date`, `layerScope: String?` (Phase 6 schema reservation, D-H2 note).
- [ ] `effectiveInstances()` dedup rule: for each `(opName, multiPriority)` keep the single latest instance at-or-before `position`; result sorted by `iopOrder` (Darktable `history.c:1600-1607` translation — test pins it).
- [ ] `HistoryHash.hash(instances:decodeParamsHash:) -> UInt64`: FNV-1a over enabled instances in v50 order, fields in fixed order `(opName ‖ multiPriority ‖ version ‖ enabled? absent : paramsData)`; cross-process stable (StableHash vectors, never `Hasher`).
- [ ] `PipeCoordinator`: `beginContinuousEdit()/commitContinuousEdit(label:)` (D-H1) + `historyDidChange()` re-materialization; EditorState owns `var history: HistoryStack` and commits on `commitContinuousEdit`.
- [ ] `TilingPlan` public pure API: `tiles(forWidth:height:maxTileBytes:bytesPerPixel:overlap:) -> [Tile]`; tested; unwired into `processRec` (explicit TODO comment referencing Phase 5).
- [ ] `HistoryStackTests` green: commit/undo/redo/jump semantics, dedup rule, hash vectors, Codable round-trip of the stack (the schema 02-06 persists).

## Reversibility gates (one-way / costly decisions)

- **D-H1 (drag-end granularity) — COSTLY**: history semantics are sidecar-schema-coupled (D-S1); changing granularity after users have sidecars = migration. Locked by checkpoint BEFORE `HistoryStack.commit` semantics are written.
- **D-H2 (unlimited history) + D-H3 (no named snapshots; jump-to-any-point instead) — locked in the same checkpoint** (D-H3 defers snapshots to Phase 6; the `layerScope` field reservation is the forward-compatibility hook).
- **Inline-snapshot HistoryItem design — COSTLY** (determines sidecar size shape + effectiveInstances purity; research §4.1 rationale recorded in the checkpoint).
- **`ModuleInstance` field set + Codable spelling — ONE-WAY once sidecars exist (02-06)**: renames after 02-06 ship = migration. Locked now, consumed by 02-06 unchanged.

  - `public mutating func commit(_ snapshot: ModuleInstance, label: String, layerScope: String? = nil)` — truncate `items[position+1...]`, append, `position = items.count - 1` (D-H1: drag-end emits this once).

- All pure value semantics (no Metal, no actor) — trivially testable, sidecar-shaped by construction.

**acceptance_criteria:**
- `commit → undo → redo` restores identical stacks (`Equatable`).
- `commit` after `undo` truncates the redo tail (test).
- Dedup: two instances same `(opName, multiPriority)` different `id`s → `effectiveInstances()` returns the later one only (test in 02-05-07).
- `jump(to:)` clamps out-of-range indices (test).
