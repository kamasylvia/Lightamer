# Plan 02-01 — Tracer: issue #1 fix (D-X1) + CIContext render-to-texture warm-up spike + StableHash

## Goal

Open the load-bearing phase with three small, independent deliverables that everything else in Phase 2 stands on:

1. **issue #1 fix (D-X1)** — the JPEG-black-screen root cause was a dual render path: `load()`'s decodeTask renders AND `EditorAreaView`'s `.task(id: loadedImageURL)` → `renderDisplayTexture` races it (the `.task` fires while `image` is still nil → skip → black frame on the reopened image). This plan makes `load()`'s decodeTask the **only** producer of `displayTexture`: delete the view-level `.task(id:)` trigger, converge `renderDisplayTexture` into a URL-guard-free `rerender()` (the future param-driven re-render entry the Phase 2 coordinator calls), and delete the `displayTextureRenderedForURL` idempotence field — idempotence now comes from having exactly one caller.
2. **CIContext render-to-texture warm-up spike (decode leg)** — Phase 1 established that on this host `CIContext.render(_:toMTLTexture:)` silently writes nothing on the **first** render (6/6) while bitmap+replace is byte-correct (spike-b: `cached-frame 15.6ms`, first-render-empty 6/6). Research §5 hypothesis: a throwaway warm-up render after context creation un-breaks the direct path, which would save the float32 CPU round-trip on the PREVIEW leg. The spike measures it headlessly and decides the decode leg (`CIImage → pipe input plane`): direct render-to-texture **iff** warm-up makes it reliable; bitmap+replace stays as the documented fallback in every outcome. Per research §5: **the drag hot path is all-Metal regardless of spike outcome** — the spike only decides the decode leg and the FULL path.
3. **`StableHash` (FNV-1a 64)** — the shared hashing primitive for PipeCacheKey (02-02), history paramsHash (02-05), and sidecar drift detection (02-06). Swift's `Hasher` re-seeds per process and is BANNED for anything persisted or cache-keyed (research Risks #2 — code-review red line).

**D-X2** (probe retirement) rides at the end: the drawable readback probe (`EditorMTKView.swift:183-203`) and the RENDER/DRAW/UPDATE debug logs are removed only after the tracer sequence verifies green.

## Tracer vertebra mapping

Wave 1 tracer plan. UAT issue #1 sequence, now green: **open JPEG → displays; open ARW → displays; reopen JPEG → displays.** After this plan the display chain has exactly one render initiator (decodeTask → `RenderPipeline` → `displayTexture` → blit), the decode-leg path is decided and documented, and `StableHash` exists for every later hash consumer. Plans 02-02..02-06 plug the recursive pipe, cache, terminal trio, history, and sidecar into this single-path skeleton.

## Task 02-01-04 — `StableHash` (Core/Foundation, public) — FNV-1a 64 primitive

**kind:** code

**read_first:**
- `.planning/phases/02-pixelpipe-core-color-management-history-stack/02-RESEARCH.md` — §1.2 (`StableHash` sketch), §4.2 (why NOT Swift `Hasher` — per-process seed), Risks #2 (code-review red line)
- `LightamerCore/API.md` — Foundation section (append entry)
- FNV-1a 64 reference: offset basis `0xcbf29ce484222325`, prime `0x00000100000001b3` (public domain spec)

**action:** Create `LightamerCore/Sources/Foundation/StableHash.swift`:
```swift
/// Stable 64-bit FNV-1a — the ONLY hash allowed in cache keys, history
/// hashes, and sidecar drift detection. Swift `Hasher` is seeded per
/// process and must never cross a persistence boundary (02-RESEARCH §4.2,
/// Risks #2). Mirrors Darktable dt_hash's role (pixelpipe_cache.c:120).
public enum StableHash {
    public static let fnvOffsetBasis: UInt64 = 0xcbf29ce484222325
    public static func combine(_ seed: UInt64, _ bytes: UnsafeRawBufferPointer) -> UInt64
    public static func hash(_ data: some DataProtocol) -> UInt64
    public static func hash(_ string: some StringProtocol) -> UInt64   // UTF-8 bytes
}
```
Doc comments must name the three consumers (PipeCacheKey 02-02, paramsHash/HistoryHash 02-05, sidecar drift 02-06) so the "stable" contract is load-bearing text. Append the public-surface line to `LightamerCore/API.md` (Foundation section).

**acceptance_criteria:**
- `StableHashTests.swift` (new, `Tests/LightamerTests/`, plain `import LightamerCore`) asserts: `StableHash.hash("") == 0xcbf29ce484222325`; `StableHash.hash("foobar") == 0x85944171f73967e8` (published FNV-1a 64 vector); `hash("a") != hash("b")`; determinism across two calls; byte-order sensitivity (`hash(Data([0x01,0x02])) != hash(Data([0x02,0x01]))`).
- `xcodebuild test -only-testing:LightamerTests/StableHashTests` green.
