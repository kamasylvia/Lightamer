# gpui 原型定位结论（一次性完整摘要）

**结论**：原型「滚动后拖滑杆 0–1 帧」是**探针采样混叠**，不是 gpui 重绘抑制，也不需要改产品代码。

## 触发点
`measure/FrameProbe.swift` 把整窗降为 **80×45 个点样本**（每格只取中心 1 像素）。1440×816 窗口样本行距 **18.13 px**；dt 滑杆的填充条 7 px、三角 8 px。偏移 602 时 module 11 track 在 y=174.5（条 177.5–184.5、三角 176.5–182.5），最近样本行 172.27 / 190.40 → **整条落在两行之间的空隙**，0 命中。偏移 0 时拖的是 module 1（canvas y=238.5，条 241.5–248.5），样本行 244.8 命中 → 13–14 帧。同一代码，换一行 y 就从 14 变 1。

## 证据（两个口径）
- 最小程序同一 run 双打分：dt 7px 条 + 密集 480×400 = **40/40**，稀疏 80×45 = **0/40**。
- 最小程序只改图元高度：7 px 单 quad = 0/40；20 px quad = 40/40。
- 原型同一 run 双打分：拖动 @602 = 密集 **26/40**、稀疏 **2/40**；拖动 @0 = 25 / 14；定时器 @602 = 38 / 38；43 次滚轮 = 38/43 变化帧。
- 拖动中 12 张实拍：滑杆带区连续 5 帧变化（1,479–6,890 设备像素/帧），松手后归零。
- 事件→首帧延迟中位 4.9 ms（@602），送达事件 29/40（8 ms 合成步长被 macOS 合并）。

## 修了什么
渲染路径**无需修改**：`dist/proto-pre-fixed` = 干净重建（与 proto-pre-clean 字节相同，sha256 `98bb3430ba7b…`），stderr 为空、无色条、无日志副作用。修复落在**测量口径**：改用 `measure/frameprobe-dual`（480×400，判据不变），或做 ROI 差分。

## 对 #27
在 gpui 上写 dt 式滑杆不须规避任何写法；必须避免的是用「全窗 80×45 点采样」判小图元重绘。样本间距应 ≤ 图元最短边的一半（1440×816 全窗等效 ≥320×180）。

## 未达项
