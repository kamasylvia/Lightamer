# Plan 04-02 — crop + flip + overlay 手柄（ROI 协商首批消费者）

## Goal

交付 IOP-GEO-01（crop，含比例锁）与 IOP-GEO-04（flip/orientation），作为 **04-01 ROI 协商的首批真模块**：crop 的 `modifyROIOut` 前向收缩让下游平面按裁切窗口原生分配（SC#4 断言①的兑现者）；flip 是纯索引映射（零采样，parity <1e-6 可达）。UI 侧交付 D-G6 的 overlay 手柄（角落拖拽 + 网格线 + 比例锁）与面板，交互走 D-H1 三件套，**live 语义用「crop 临时 disabled + 暗膜」规避拖动全链 miss**（04-RESEARCH §1 gotcha 的 UI 层规避）。

**v50 硬约束**：flip(16.0) 必须先于 crop(24.5)（dt `iop_order.c:810-812`「crop GUI broken if flip is done on top」）——默认链自然满足，**勿调序**。crop 槽位 24.5 特意排在 toneequal(24.0)（最后一个需要扩大 roi_in 的模块）之后——ROI 协商语义就是这条注释的机制化。

## Must-haves

- `CropParams`：fraction 语义（left/top/right/bottom ∈ [0,1]，分辨率无关）+ ratioN/ratioD（-1 = free）；MIN_CROP_SIZE 短边 ≥1% fraction、≥4px
- crop `modifyROIOut` = dt `crop.c:517-531` 直译；`modifyROIIn` = `:576-592` 直译（偏移回加 + clamp bufIn）；`process` = 同尺寸窗口拷贝（复用 `PixelPipe.blit`，L008 endEncoding 纪律已合规）
- `FlipOrientation` 8 态枚举（H/V 镜像 + 90° 步进含 XY 交换，dt ORIENTATION 位语义）+ `flip_apply` 索引重排 kernel；90° 时 modifyROIOut 交换 W/H
- crop/flip 钉参 golden：**dt-cli EXR 直用**（纯索引拷贝零自由度——L017 的例外；仍先跑平场 + 变化图像双重 probe 再首用）
- overlay：4 角 + 4 边 + 中心 hit-test（dt `_grab_region_t` 16 态）、三分/黄金网格、比例锁（短边贴比例、长边从动，clamp [0,1]²）
- 拖动交互恰 1 条 history commit（D-H1 三件套）；编辑期间全图渲染 + 暗膜（cache 友好）
- 公共 aspect-fit 工具抽取（PipeCoordinator.viewportUV / EditorMTKView.aspectFitUniforms 之外的第三处使用——research §6 遗留债顺手还）
- String Catalog zh/en 同批
