# Plan 02-04 — Terminal trio (colorin/colorout/gamma) + ModuleRegistry + golden dual-criteria harness

## Goal

Make display color *correct* (SC#1, COLOR-01) and lock the module registry seam (COLOR-04's extension point), then prove correctness with the D-COL1 golden harness.

**The semantic fact that shapes everything** (research §3.1 — must be written into architecture docs this plan): CIRAW output is **already-developed** imagery (demosaic + WB + camera matrix + baseline exposure + tone all internal). Lightamer's `colorin` is therefore NOT Darktable's camera-RGB→working conversion — it is identity/normalization with a reserved input-profile parameter (COLOR-04's DCP hook). The real display transform lives in `colorout` (gamut matrix) + `gamma` (TRC encode → `.bgra8Unorm`). This "pipeline input is display-developed domain, not scene-linear" note is the Phase 3 filmic-port calibration warning — document it where Phase 3 authors will read it.

- **colorin** (v50 order 28.0): identity kernel + debug assert input is working-space; `Params.inputProfile` reserved (COLOR-04: Phase 13+ DCP injection point).
- **colorout** (70.0): dual path — (a) **Metal fast path**: compile-time constant matrices for linear Rec2020 → Display P3 / sRGB linear (function-constants, D-17), covering the known-`NSScreen.colorSpace` name table (D-COL2); (b) **ColorSync precise path**: `CIContext.render(toBitmap:..., colorSpace: screen.colorSpace.cgColorSpace)` for any other profile — also the harness's independent baseline (D-COL1 criterion 2). `Params.outputProfile` reserved per D-COL3 (Phase 13 printer profiles plug in here).
- **gamma** (78.0, pipe tail): sRGB segmented TRC encode (≤0.04045 linear leg / 2.4 power leg), clamp >1.0 (D-COL4: pipe interior stays float32 unclamped; EDR is Phase 8), write `.bgra8Unorm` display texture. Cached planes stop at **colorout output** (float linear, reusable across screens); gamma is the cheap display handoff (~1ms at 2560px) — window/screen changes re-run only gamma.

**D-COL1 acceptance is dual-criterion** (research §3.5 — the neutral-gray test alone CANNOT catch TRC/gamut mismatches, so the harness needs both):
1. Neutrality: ColorChecker-class gray patches `|R−G|, |G−B| < 2/255` after the full chain.
2. Cross-consistency: pipe output vs `CIContext` ColorSync direct render, per-pixel `< 2/255`.

Plus **`ModuleRegistry`** (Core, public): `opName → module factory` for sidecar decoding (02-06) and default-chain assembly; Core hosts the terminal trio (pipeline infrastructure — tests run the pipe with zero LightamerIOP dependency), LightamerIOP registers its modules via a populate hook (testGain, DEBUG-only).

## Tracer vertebra mapping

Wave 3, after the pipe family exists. After 02-04: open a RAW → colors are *right* (neutral target passes both criteria), the default chain `[colorin, colorout, gamma]` is cache-warm, and a screen change re-runs only the tail. SC#1's verification lives here; SC#2's full-chain cache assertions land in the harness.

   - `process`: output texture is `.bgra8Unorm` (pipe allocates the FINAL plane in display format; intermediate planes stay `.rgba32Float`); kernel `gamma_encode`: per channel `c <= 0.04045 ? c/12.92 : pow((c+0.055)/1.055, 2.4)`, computed in float (L006), clamped to [0,1] (D-COL4: clamping happens HERE only), write `float4(r,g,b,1)` — Metal converts on write to the unorm texture (verify compute-write to `.bgra8Unorm` compiles; if the format rejects compute writes, fall back to writing `.rgba8Unorm` + a 3-line channel-swap in the blit shader — record whichever in API.md).

2. `PixelPipe` tail policy: `run(...)` for `.preview`/`.thumbnail` allocates the final plane `.bgra8Unorm` and routes it through gamma; cached planes at positions < gamma stay float32 (document in the pipe header). FULL: same terminal treatment (its output is also display-format when run for 100% viewing).

**acceptance_criteria:**
- TRC values unit-tested (02-04-07): 0.0 → 0.0; 0.04045 → ≈0.04045/12.92; 1.0 → 1.0; 0.5 → ≈0.7354 (±0.001); 2.0 → 1.0 (clamp).
