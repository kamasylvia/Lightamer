## 背景

Lightamer 正在从 Swift 全量重写成 Rust。阶段 A（地基）在连跑，已经过半。阶段 B 是第 0 期：21 个 darktable 模块加会话、图库、导出和界面，做完是首个可用版。

现有的计划在 `.work/gsd/phases/rust-core/PLAN.md`，它的阶段 B 那一部分（§3 的 B1 到 B20）**有两处已经和定稿的架构对不上**：

你的任务：**重写阶段 B 的逐波计划**，产出一份新文件。不动原计划，不动任何代码。

- 修改历史只存会话数据库（SQLite，WAL），导入默认复制进 `Capture/`，原地引用是显式选项，暂时不做目录模式。

## 要做的

**1. 会话包和数据库的设计（这是新计划的地基，先写它）。**

- 磁盘形态：一个普通文件夹，里面有什么、各叫什么、哪些是可以重建的派生物。按 `ARCHITECTURE.md` §2，去掉每张图的设置文件。
- SQLite 的表：每张照片的设置、历史栈的每一步、处理版本号、缓存键、评分和旗标、关键词、相册和收藏、引用式导入的路径、Trash 里记住的原路径。你自己定表，逐张表写清楚列、键和索引。
- 历史怎样存。我们的模型是每一步存一份完整的快照。直接每步一份 JSON 最简单，但要算清楚占用，并说明你的办法。可以考虑的方向（由你判断，不强制）：快照按内容去重，内容相同的步指向同一份。
- 版本和迁移：库的版本号记在哪、怎样升级、升级前留什么。
- 锁：同一会话只许一个写者，怎样表达，持有人是谁。
- 备份和恢复、校验：各用什么办法，为什么。
- 崩溃：写到一半断电或强退之后，重开是什么样。

**2. 三个代价的正面回答。** 用户选了只存数据库，`ARCHITECTURE.md` 自己列过这条路的三个代价，新计划要逐条给出处理办法和验证它的那一波：

- 单张图拷出去不带调整。确认用户的接受方式（修订 A-15 写的是：导出命令可选，第 0 期不做）。新计划里写明第 0 期不做什么。
- 库坏了全丢。靠备份和校验。
- 批量粘贴的性能。阶段 A 从 LightCraft 量到的门（修订 A-10）：一万张粘贴在一秒内可见；切图暖启动不超过 0.72 秒；可见的缩略图约 0.5 秒刷新。新计划要写明这三个数各在哪一波量、怎样量。

依赖选型：倾向 `rusqlite` 带内嵌的 SQLite（同步、成熟）。你去查实际情况： crates.io 上的当前版本、许可证、会带进哪些传递依赖、这些许可证在不在仓库的 `Scripts/licenses-allow.txt` 里（**只查，不改它**）、内嵌编译对冷构建时间的影响（现有的门是冷构建 360 秒，`Scripts/rust-budget.sh`）。有更好的选择就提出来比较。

**3. 逐波重写 B1 到 B20。** 卡片格式照 `PLAN.md` §3 现有的十项（目标、范围、输入、产出、验收、对照、回退、估时、风险、任务书草案），不要自创格式。要求：

- 和会话、历史、图库无关的波（模块和管线的那些）原来写得对的保留，只做必要的修订；说明哪些一字未改。
- 原来的 B12、B13、B14、B15、B16、B19、B20 要重写。把 T-A8 的每一条命令分配到具体的波（哪一波登记它、实现它、测它），一张表，不许有命令没有归属，也不许有命令被分给两波。
- 每一波停下时向用户汇报什么：能看见什么、怎样验收。要写得让没看过内部的人也知道这一波做成了没有。
- 新增的 crate 或依赖要标出来，并说明它落在分层的哪一层（T-F9）。能不新增就不新增。
- Apple 能力（缩略图要用 ImageIO 读内嵌的预览图等）只能经 `dt-apple`，标出哪一波要往 `dt-apple` 里加什么。
- 界面从 B17 起只用 `execute` 和快照，标明它依赖前面哪几波的命令。
- 首个可用版仍是 B20 做完：导入、在会话里浏览、进暗房、导出到 `Output/`、备份和恢复，走成一个闭环；21 个模块对 darktable 官方版的对照通过。
- 估时照原计划的写法（几条 lane、每条几小时），给出新的合计，并和原计划的数字对比。
- 每张卡的风险一栏要写真风险，不要写「无」。

**4. 需要用户定的事。** 只列真的需要用户拍板的，每条给出你的推荐和理由。architecture 调研里没查到的那些（T-A9），哪些被 A-15 解决了、哪些还在，也交代一句。

**5. 和原计划的差异表。** 一张表：每一波，原计划是什么，新计划是什么，为什么改，依据是哪一条修订。

**6. 自审之后才能交。** 写完后换一个角度把它当别人的计划来挑：哪一波的范围大到一条 lane 做不完；哪一条命令的实现依赖了还没做的东西；三个性能数有没有落空；有没有哪里偷偷带回了每张图的设置文件或 XMP；有没有哪一波没停下就进下一波。挑出来的问题当场改，改动记在文末。
