### 塔台的三条裁定（先改，它们决定下面几条怎么改）

**T4 过曝标注：语义不变，持久化挪到 B12′（解决 E1）。** 规划 lane 把 overexposed 的阈值定为会话级的显示辅助参数、不进历史栈、切图保持，这是对的，不要推翻。塔台核过 darktable 的源码（`release-5.7.0`）：`src/iop/overexposed.c` 第 78 行给它的标志是 `IOP_FLAGS_HIDDEN | IOP_FLAGS_ONE_INSTANCE | IOP_FLAGS_NO_HISTORY_STACK`，阈值读的是全局的 `dev->overexposed`，不在照片的历史里；`src/iop/rawoverexposed.c` 第 75 行同款。错的只有一处：它让 B6 把阈值存进 `_meta.display_aux`，而那张表要到 B12′ 才建。改成：

- **B6 只做行为和内存里的状态。** 阈值放在引擎的会话级内存状态里：进程启动时是默认值，切图保持，不进任何照片的历史栈。不落盘——B6 那一刻还没有会话库。「重开应用回到默认值」是这一波的已知行为，写进 B6 的验收和它卡里的说明。B6 卡里「阈值存会话级 `_meta.display_aux`」那句删掉。
- **B12′ 把持久化补上。** 范围栏加一项：`_meta` 里的 `display_aux`（会话级显示辅助参数的 JSON）+ 读写它的数据访问 + `session.verify` 校验它能解析（这条校验原来写在 B6 的风险栏里，一起挪过来）。验收加一条：改过曝阈值，关会话，重开，阈值还在。
- **引擎的接口用一条单独的命令，不在 `develop.set` 里开白名单。** 命令叫 `display.set`（参数：模块标识 + 补丁），它改的是会话级的显示辅助参数，从不记历史步。这样 A7a「改历史的命令恰好记一步」不用加例外。B6 登记这条命令；T-B2 里补上它，标「塔台补入」，和 `library.relink` 同样的注记。B15 的条数不受影响。
- **「不进历史栈」的依据是模块描述里的标志，不是引擎里手写的名单。** 描述带着 darktable 的标志；标志说不进历史栈的模块（darktable 里是 overexposed、rawoverexposed、finalscale 三个）不能经 `develop.set` 改，那会是参数错误，它们只能经 `display.set` 改。A3 的描述里现在有没有这一位（`crates/dt-iop-traits/src/lib.rs` 里 `history.doc_level` 那一带），B6 的 lane 动手前先核，没有就按 darktable 的 `IOP_FLAGS_NO_HISTORY_STACK` 补上——描述是模块自己带的，不算中心名单。B6 的风险栏照这个写，删掉「白名单」那种说法。
- **「不进导出」保留，并写明依据。** darktable 里它只在带界面的完整管线里启用（`overexposed.c` 第 406 行：`piece->enabled = … && dt_pipe_is_full(piece->pipe) && self->dev->gui_attached`）。B6 的产出里写明我们的管线照这个条件排除它。

**T5 库和内存谁先谁后（解决 m9）。** B13′ 卡的风险栏现在写「库事务先提交，内存随后应用，失败回滚库事务」，这是错的，已提交的事务回滚不了。在 `PLAN-B.md` §1 里加一小节「§1.8 命令落库的次序」，写这条规则，并把 B13′ 风险栏那句换成指向它：

- 库是真相，内存是它的镜像。
- 一条要落库的命令分三步：先把新的内存状态算好（这一步可以失败，失败时库一个字节都不碰）；再跑库事务并提交；最后把算好的状态换进内存。
- 第三步不会失败，因为它要换进去的东西第一步就算好了。
- 库事务失败：返回错误，内存和库都没变。A7a「出错后状态不变」的契约在落库之后仍然是这一句，只是「状态」多了一半。
- 进程在提交之后、换进内存之前被杀：重开后以库为准，什么都不会丢。

**T6 命令和作业的界线（解决 m10）。** A7a 的契约是「命令是快的，不碰磁盘」，那是 A7a 那一波（数据全在内存）的口径。在 `PLAN-B.md` §1 里加一小节「§1.9 命令和作业的界线」，写定稿：

- 命令只做**有界**的活：内存里的状态变更，加上至多一次有界的落盘（B13′ 起的一条小事务，比如一万张粘贴的那一个事务）。
- **无界**的活不许放在命令里，由命令启动成一个作业：拷文件、扫文件夹、解码、渲染、编码、整包备份。作业在工作线程上跑，能取消，进度经事件报回来；作业的产物回到引擎线程之后才由引擎落盘。
- 然后在三张卡里各补上作业边界：B12′（`session.backup`、`session.restore` 是作业；`session.open` 的失联扫描已经是作业，保留）、B15（导入的复制、`library.sync` 的扫描、缩略图的生成是作业；命令本身立即返回）、B16（导出是作业，卡里已有进度和取消，补一句它遵守这一节）。每张卡的验收里各加一条：命令在作业跑完之前就返回了，并且有测试证明。
