## 要回答的问题

每个答案带证据：文件路径、行数、类型名或函数名。行数写出得出它的命令。LightCraft 的设计意图如果文档里写了，引用原文；文档没写的标「推断」。

**F1 分层。** 它的工作区怎样分层，每一层放什么，依赖方向是什么，由什么检查强制（找出那个检查的实现，写清它查什么、不查什么）。画一张层与 crate 的对照表。

**F2 引擎与命令。** 「一切皆命令」具体怎样实现：命令怎样声明，参数怎样传，怎样分发，历史与撤销怎样接，渲染和导出的作业怎样排队与取消。界面、命令行、JSON 控制通道、MCP 五个前端是怎样共用同一个分发口的。MCP 的单写者锁和连接转发怎样做。下层怎样做到不知道界面的存在。

**F3 编辑模型。** 设置怎样表示，怎样演进，控制规格单表是什么、谁在用，每张照片的处理版本号怎样存、何时开新号、旧号怎样冻结。

**F4 管线。** 一个处理步骤的接口长什么样，CPU 参考管线怎样组织（整帧还是分块，缓存什么），预览与缩略图走什么路，取消与「只要最新」怎样处理，内存的准入控制怎样做（`sysmem`、`work_gate` 一类），GPU 孪生与回退阶梯怎样接。

**F5 图库与批量。** 图库的存储模型（说是只追加的日志，核实），缩略图与预览缓存怎样组织，导入怎样做。**专门查清它为什么快**：批量粘贴一万张 347 毫秒、热切换 0.72 秒、可见缩略图约 0.5 秒刷新，各自靠的是什么机制，哪些是立即做的、哪些是拖到以后做的。给出代码位置。

**F6 元数据与 XMP。** 它怎样写自己的命名空间，怎样只替换自己拥有的属性而逐字节保留外来的内容，怎样近似映射 Lightroom 的字段。

**F7 工程纪律。** `testkit` 里有什么，等价性门怎样做，分层检查、归属检查、永不崩溃一类的 lint 各是什么。

**F8 取舍清单。** 对上面每一块，给我们一个判定：**照搬、改造、不学**，各带理由。理由要对着我们已定的裁决说。已知不学的三条：自研 RAW 解码器（我们用 rawspeed）、egui 界面（我们用 gpui 族）、跨平台解码与色彩底座（我们的 Apple 能力独占一个模块，只在 macOS 构建里存在）。模块自动发现和注册是用户的要求，不能退回写名单。

**F9 映射表。** LightCraft 的 crate、我们现在计划里的 crate、darktable 的概念、计划的波次，四者对成一张表。然后给出**我们新的分层 crate 布局**：名字、层号、允许依赖谁。写明 darktable 兼容的各块放在哪（模块描述、顺序、参数布局、历史读取），Apple 模块放在哪一层，gpui 界面放在哪，命令行与对照工具放在哪，LightCraft 独有的好东西放在哪（处理版本号、准入控制、测试套件）。A3 正在做的模块描述与自动发现，在新布局里落在哪几个 crate，怎么搬。

**F10 可以直接取用的代码。** 逐项列：路径、行数、它做什么、取用时 `NOTICE` 要写什么。只列值得原样取用或小幅改造的，比如分层检查的脚本、命令注册的骨架、准入控制、处理版本号的辅助代码。其余归为「学设计、自己写」。

**F11 对计划的影响。** 逐波写：

- 阶段 A：哪几波不变，哪几波要改内容，要新增哪几波。至少有：A3 之后插一波重排（按 F9 的布局重排 crate，加上强制依赖方向的检查）；A7a 改成按「一切皆命令」的命令分发口来做。给出阶段 A 新的波次表。
- 阶段 B：每张卡片用一两句话写它落到哪些新 crate、有没有内容变化。重点是 B1（管线内核）、B12 和 B13（历史读写与图库）、B14（蒙版与混合）、B15（导入、图库、缩略图）、B16（导出）、B17 到 B19（界面）。
- 估时的变化：加了几条 lane，减了几条。

**F12 拉不到一起的地方。** 两条要求冲突或别扭的地方，逐处写：冲突是什么，LightCraft 怎样做，darktable 怎样做，你建议怎样调和，代价是什么。至少看这几处：设置模型对 darktable 的整块参数；处理步骤的接口对 darktable 的回调、感兴趣区域与分块；图库为真相对两处都存；预览与缩略图的路径；没有自研去马赛克。
