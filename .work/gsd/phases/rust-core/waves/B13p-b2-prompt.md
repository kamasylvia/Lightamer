## 要做的

**1. 两条新命令。** 标识照 T-B2，经分发口登记，每条带机器可读的参数清单。两条都在草稿会话和真实会话上能用，都按「先算好、提交、再换入」落库，**所有目标照片在同一条事务里**，每张目标各记一步，目标的处理版本号不变。

- `develop.sync`：从一张源照片的当前设置，把选中的部分同步到一批目标照片。参数：源照片、目标照片、选择。
- `develop.merge`：把剪贴板里选中的部分合并到一批目标照片。参数：目标照片、选择。剪贴板是空的是错。
- 「选择」有三种：不给（全部模块）；给模块（只管这些模块）；给到参数（形如 `模块.参数`，只覆盖这些参数）。模块级：选中的模块实例在目标里替换或新增，没选中的一个都不动。参数级：只覆盖选中的参数，目标里没有这个模块就新建一个只带这些参数的实例。历史模型里那个纯函数已经实现了这些规矩，你负责把参数接上去。
- 选择里出现不认识的模块或不认识的参数名，是参数错误，什么都不写。源照片不存在，报和别的命令一样的「没有这张照片」。
- 每条命令的步数标签就是命令的标识。

**2. 命令行在真实会话上把照片打印出来。** `run --file` 现在每执行完一行，会打印草稿会话里照片的「步数和游标」。真实会话上也这样做：**文件里任何一行出现过的照片标识**（`ids` 里的、`id` 里的），每执行完一行之后都打印它的步数和游标。标识很长，打印前 8 个字符就够，用法说明里写明。会话还没打开的时候打印不了，那就打开之后才开始打印。

**3. 计时工具。** 给 `lightamer-cli` 加一个 `bench` 子命令。它是开发用的工具，**不是导入命令**（真正的导入在 B15）——帮助文字和文档里都要写明。命令行工具因此要直接依赖会话库这个 crate（它本来就是不参与分层检查的工具）。

- `bench setup --parent 目录 --name 名字 --photos N`：建一个会话，往 `Capture/` 里放 N 个空的占位文件并登记。打印会话的位置和登记的数量。
- `bench paste --session 位置 --photos N --runs 3`：引擎打开会话；先给一张源照片设一个参数并拷贝到剪贴板（这一步不计时）；然后量粘贴到 N 张照片：**从调用那条命令起，到它返回、事件全部送达止**。每一轮都要从同一个起点出发——上一轮粘贴的效果怎么撤掉、或者换一批新登记的照片，你定，写进报告。至少量三轮，报中位数。
- 一万张那一次是硬门：`--photos 10000`，门是一秒。**要用发行版构建来量**（`cargo build --release -p lightamer-cli`，然后跑 `target/release/lightamer-cli`），因为用户用的是发行版；调试版的数可以另报，不作数。
- 机器忙的时候量出来的不算：照 `Scripts/rust-budget.sh` 里现成的判断办法，负载高就打印「测不准」并跳过，不判过也不过不了。
- 输出：每轮的总时间、中位数、送达的事件数（应该等于 N）、过没过。门不过，退出码非零。

**4. 门。** 上一段里，一万张粘贴走的是「逐张加载整个栈、再提交」，没有另开近路。库那一侧一万步是 0.34 到 0.36 秒；引擎这一侧加上逐张加载，端到端很可能贴着门。你去量：

- 过了：把数报上来，再说一句余量有多大。
- 没过：把时间拆开——读库、算、写库各占多少。能调的调（比如不必把整个栈读出来就能推一步的近路、一次读一批而不是一张一张查）。调完再量。**仍不过，如实报告**，附上拆开的数和你试过的办法。

**5. 给用户看的演示脚本。** `Scripts/rust-history-demo.sh`，在临时目录里把这一波做成的事从头演一遍，每一步打印结果：

1. 建一个会话，登记三张空的占位照片。
2. 改 A 两次、撤销一次、重做一次；关会话。重开，打印三张照片的步数和游标——和关之前一样。
3. 强退：后台起一个进程，打开会话，给一张照片提交三步，再开始一次拖动并更新一下但不松手，然后握着会话不放；前台确认它握着；强杀它；重开，打印那张照片：三步都在，游标在最新的一步，拖动的那个值不在。
4. 同步与合并：从 A 把一个模块同步到 B；把剪贴板里选中的模块合并到 C。打印各自的步数和标签。
5. 一万张粘贴的计时：打印发行版量出来的数和过没过。
6. 清掉临时目录。

脚本只用自己的临时目录和空的占位文件，不读用户照片库，不写真实的应用支持目录。强杀的只能是你自己刚起的那个进程。跑完退出 0。

**6. 文档。** `docs/SESSION.md` 补两条新命令、命令行在真实会话上的输出、计时工具怎样用。`crates/README.md` 里命令行工具那一行改成现在的内容。
