## 现在的起点（塔台看的，每一条你自己核）

- 管线有一个同步的渲染入口：给它节点、模块来源、输入画面、输入标识、处理版本号、输出区域、取消检查，它交出输出画面。
- 引擎有作业池（四个线程）、事件（作业的开始、进度、结束；照片变了；剪贴板变了）、快照。会话命令里备份、恢复、扫描已经是「命令登记启动就返回，作业去做，进度经事件报」。

- 引擎还不依赖管线的 crate。

## 要做的

**1. 引擎的注入口**（由嵌入引擎的一方注入，引擎自己不去找）：

- **输入来源**：一个 trait——给照片标识，交出画面、图像信息和输入标识，或者分了类型的错误。它可能很慢（将来是解码），所以只在作业线程里调用。
- **模块来源**：按标识找到模块（`Arc<dyn IopModule>`）。
- 两个都可以不注入（默认是空的）：没有输入来源时，渲染请求返回分了类型的错误（在命令这一层，不起作业）；模块来源是空的时候链是空的，输出等于输入。
- 管线实例由引擎自己建，每种一个，预算按物理内存。

**2. 两条命令**（经分发口登记，带机器可读的参数清单）：

- `render.request { photo, kind }`，`kind` 是四种实例之一。**立即返回**代号和作业编号。每个（照片，实例）有一个递增的代号。同一个（照片，实例）已经有在飞的渲染时：那一个**被取代**——它的取消标志置位（这个标志就是传给管线的取消检查），它的结果到达时丢弃。不同照片、不同实例之间互不影响。
- `render.cancel { photo, kind }`：取消在飞的那一个，不起新的。没有在飞的时候怎样办，你定并写明。

**3. 作业和结果。**

- 作业在作业池的线程里做：取这张照片当前的历史 → 按注册表的顺序链排出节点（模块来源里找不到的模块跳过，并记进这次渲染的记录）→ 向输入来源要画面 → 调管线的渲染。以**请求那一刻**的当前设置为准：渲染中途用户又改了参数，这一次的结果对应的是请求时的设置；新的请求会带来新的一代。
- 结果怎样回来：画面经作业消息回到引擎，在引擎自己的线程里处理（现成的 `collect` 那条路），作业线程不碰引擎的状态。
- 引擎为每个（照片，实例）保留最新一代完成的画面，直到被新的一代取代或会话关闭；给一个读取它的办法（方法，不是命令）。
- 事件：`RenderReady { photo, kind, generation }` 只为最新一代发；最新一代失败时 `RenderFailed { photo, kind, generation, reason }`；被取代的那一代不发渲染事件（作业通用的开始、进度、结束事件照常）。
- 管线的渲染要独占那个实例：同一种实例的两个作业不能同时渲染。你怎样保证（一把锁，还是每种实例一条专属通道），以及被取代的作业多快让出（取消在节点之间、块之间查，最坏是一个 `process` 调用的时长），写进报告。

**4. 草稿会话和真实会话都能用。** 真实会话上读当前设置走库里现成的读法；**渲染不写库**。

**5. 每次渲染的记录。** 管线或引擎要给出上一次渲染每个节点的情形：命中还是重算了、`process` 被调了几次、花了多少毫秒。只读的办法，给演示和测试用。管线 crate 只许为这一条加东西（逐处列进报告），别的不动。

**6. 命令行的演示工具。** `lightamer-cli` 加一个子命令（比如 `render-demo`）：内置一个合成的输入来源（渐变画面，尺寸可以给）和一个内置的私有模块（乘一个增益，定义在命令行工具里——测试套件那个 crate 只许作开发依赖），在临时目录里走一遍，每一步打印结果：

  1. 建会话，登记几张空的占位照片，给一张照片的链上放五个增益模块。
  2. 渲染一次（预览实例）：打印每个节点命中还是重算、`process` 的次数、毫秒数，一张文字表。
  3. 改第三位的增益，再渲染：前两位命中，后两位重算。这就是计划卡片要的「改一个参数只重算下游」的演示。
  4. 连发三代（三次请求各改一次增益，中间不等）：打印收到的渲染事件——只有第三代的一条就绪事件——和三代各自的结局。
  5. 取消：起一个慢的渲染，取消它，打印没有就绪事件。
  6. 空转计时（预览实例，合成画面）：每个节点的毫秒数。
  7. 清掉临时目录。

**7. 演示脚本** `Scripts/rust-render-demo.sh`：用发行版构建跑上面的子命令，每步打印结果，退出 0。只用自己的临时目录和合成的画面；不读用户照片库，不写用户真实的应用支持目录。

**8. 文档。** `docs/PIPELINE.md` 加一节「渲染作业（引擎这一侧）」：注入口、两条命令、代号和取代的规则、事件、结果的保留。`docs/SESSION.md` 里如果有命令清单，两条命令各加一行。`crates/README.md` 里改动了的行。

## 测试

每一条行为一个测试，名字能看出测的是什么。模块用假名字和假模块。**全部在临时目录里跑**，自己建、自己删；不碰用户照片库 `/Volumes/UNITEK/Cloud Drive/QSync/Medias/Photos/Workspace`（不读、不列目录），不写用户真实的应用支持目录。

- **只留最新一代**（卡片验收第六条）：慢模块，连发三代——恰好一条就绪事件，是第三代；前两代没有任何渲染事件，它们的作业以「被取消」结束；引擎保留的是第三代的画面（三代的画面内容能分辨）。
- 取消：取消之后没有就绪事件，作业以取消结束；之后新的请求照常。
- 取代的隔离：同一张照片的完整分辨率和预览互不取代；两张照片互不取代。
- 失败：模块出错、输入来源出错——最新一代一条失败事件，带原因；引擎里没有留下半截的结果；管线的预算全部归还。
- 命令先返回：慢模块下，`render.request` 在作业完成之前就返回了（断言返回时作业没完成）。
- 三种坏参数（不认识的参数、缺必填的、实例种类不对）各报分了类型的错误，没有作业被起。没有输入来源时报分了类型的错误。
- 没有模块来源：链是空的，输出逐位等于输入。
- 历史变了：请求之后改参数、不发新请求，结果对应请求那一刻的设置。
- 草稿会话和真实会话各一组；真实会话上渲染前后库里内容的汇总值不变。
- 分发口：登记表的条数；两条新命令的参数清单没有重复。
- 渲染记录：每个节点的命中或重算数，和 `process` 被调的次数对得上。
- 命令行：子命令用小画面跑通并打印。
