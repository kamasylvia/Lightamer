## 要做的

**1. 模块的接口。** 放在 `lightamer-iop-traits`。调研的草图用了关联类型（每个模块自己的参数类型和提交结果类型），那样的接口没法做成「一张表里放着各种各样的模块」——而自动发现和注册要的正是那张表。所以接口要**对象安全**：

- 每个模块能被问：标识、标志位、输入和输出的色彩空间（描述里没有填的，给默认值）。
- **提交**：给它这个实例的参数（一个 JSON 对象）和图像的信息，它交出「提交结果」——一个不透明的、可以在线程之间共享的值，每个模块自己知道怎样转回自己的类型。
- **区域**：给它提交结果和一个区域，问它输出要多大（或者反过来，给输出区域问它需要输入的哪一块）。默认都是原样。
- **分块请求**：给它提交结果和输入、输出两个区域，它报告自己要多少内存、块之间要重叠多少像素、块的位置要对齐到多少。默认值照 darktable 的默认回调。
- **处理**：给它提交结果、输入画面、输出画面、输入和输出两个区域，它把输出写出来。
- 出错返回分了类型的错误（参数不对、区域对不上、不支持的格式、后端出错），每种的说明是一句人能读的话。
- 给模块作者准备几个小工具：从参数的 JSON 对象里按名字取浮点、整数、开关、文本、浮点数组，类型不对或找不到报的是「参数不对」。

**2. 区域。** 放在 `lightamer-geom`。照 darktable 的结构：`x`、`y`、宽、高是整数，缩放是浮点。要有的运算：相交、合并、平移、按缩放换算、判空、判包含、取子区域。**换算时的取整规则必须和 darktable 一样**——去读它前推和反推时怎样算的，把规则和出处（`文件:行号`）写进代码注释和报告。整数的加减乘除不许溢出、不许下标越界（不崩溃的 lint 会逼你）。

**3. 画面。** 放在 `lightamer-raster`：

- 一块画面 = 像素缓冲 + 它所在的区域 + 像素格式。像素格式先定枚举，现在只有一种用得上：32 位浮点、四个通道、预乘的 Alpha——这是整条管线里的工作格式。别的格式（给显示用的 8 位、16 位）只是枚举里有名字。
- 缓冲从 `lightamer-sysmem` 来：**一个带硬上限的预算**，申请超过上限是错误，不是崩溃；释放要归还。预算余量随时能问。
- 画面的访问方式要让人写不出越界：按行取（给并行用：把行范围切开，各写各的，不互相别名）；按子区域取（读视图和写视图）；整体拷贝。字节大小和行列数在 64 位里算，溢出是错误。
- 图像的信息（解码之后的尺寸、相机输入的色彩空间这一类）也定义在这里，或者定义在区域那个 crate 里，你定，写明理由。

**4. 分块。** 请求的结构照 darktable 的（处理器这一侧的字段：`factor`、`maxbuf`、`overhead`、`overlap`、`align`；图形处理器那侧的字段先留着位置不填）。**决策**是一个纯函数：给它请求、输入和输出两个区域、一块画面占多少字节、预算有多少，它回答「不用分块」，或者给出块的网格——每块的位置和大小、每块实际要读的输入区域（含重叠）、块的总数。划分的算法照 darktable 的分块执行来移植（读 `tiling.c`，把公式和出处写进报告）。默认请求下的结果要和它一致。

**5. 几何链。** 放在 `lightamer-pipeline`。给它一串**按执行顺序排好的**模块实例（标识、多实例的下标、参数）和一个「按标识找模块」的来源，它做三件事：

- 提交：逐个调模块的提交，得到每个节点的提交结果。
- 前推：从最后想要的那块输出区域出发，逆着执行顺序，算出每个节点要输出多大、需要输入多大，一直推到最前面——也就是需要解码出来的那块区域。
- 反推：从最前面的输入区域顺着推回去，核对能对上。
- 节点的顺序由调用方从注册表拿（A3 的顺序链）；你这里只负责「给我一串有序的实例，我把几何算对」。来源里找不到某个模块，是错误。
- **标识不许写死在核心里**：测试里的模块用假名字，比如 `mod_a`、`mod_b`。仓库有一道检查会搜管线这个 crate 里有没有出现 darktable 的模块名。

**6. 格式协商。** 每个节点说自己要什么色彩空间进来、什么色彩空间出去。协商的结果是一张计划：相邻两个节点之间要不要插入一次色彩变换、从哪个空间到哪个空间。**这一波只做计划，不做变换**（变换在 B5 的色彩三件里）。全链都是同一种色彩空间时，计划里一处变换都没有。

**7. 四种管线实例。** 定一个枚举：完整分辨率、导出、预览、缩略图。再定一张配额表，四种各一份：内存预算、一块最多多大、缓存留多少。数字你先给一组合理的，标明「初值，B1-b 实测后再调」。

**8. 恒等模块。** 一个把输入原样抄到输出的测试模块，放在测试套件那个 crate 里（它只许作开发依赖）。后面两段都要用它。

## 测试

每一条行为一个测试，名字能看出测的是什么。

- **几何链至少八例**（计划里 B1 的第一条验收）：恒等链；一个节点把输出放大、一个节点把输出缩小；裁剪之后放大再缩小，**往返之后区域回到原样**；缩放不是整数倍时的取整；空区域；节点说「我不需要输入」；链很长时误差不累积；前推和反推对得上。每一例里，每个节点的输入区域都装得下它要的那一块。
- **分块和 darktable 一致**（第二条验收）：至少四例——放得下不分块；宽度方向要切两块；两个方向都要切；带对齐要求时块的位置落在对齐上。每一例的块数、每块的大小和重叠，是你照 darktable 的公式手算出来的，测试里写上算式。
- 区域的每个运算各至少一例，含边界情况（空、负的坐标、缩放为零或负数是错误还是空，你定并写明）。
- 画面：按行切开之后各写各的互不影响；子区域视图读写的确实是对应的那块；越界访问在编译期就被挡住，或者运行时是错误——举一个例子证明；预算超了是错误；释放之后余量回来了。
- 模块接口的小工具：五种类型各取对一次，类型不对和找不到各报一次错。
- 格式协商：全链同空间时零变换；相邻节点空间不同时计划里有且只有那一处；计划里的每一处都带着从哪个空间到哪个空间。
- 测试用小画面，不占内存。这一段不量性能。
