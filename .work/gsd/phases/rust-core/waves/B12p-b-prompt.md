## 要做的

**1. 引擎认识「真实会话」。** 现在引擎只有草稿会话（照片放内存）。加一种真实会话：引擎持有一个前一半交出来的 `Session`，也就是握着锁和数据库连接。一个引擎同一时刻只开一个会话。草稿会话原样保留，测试和对照还要用它。

**2. 七条命令。** 标识照 T-B2，一个字不改，经 A7a 的分发口登记，每条带机器可读的参数清单：

| 命令 | 做什么 | 记不记历史步 |
|---|---|---|
| `session.new` | 参数是会话名和放在哪个目录下。建会话包，建好之后引擎就开着它 | 不记 |
| `session.open` | 参数是会话文件夹或库文件的路径。已经开着会话时不能跑，返回带原因的错误。文件夹里没有库时就地补齐 | 不记 |
| `session.close` | 把日志合并进库文件，释放锁，之后引擎没有会话 | 不记 |
| `session.verify` | 只读的校验，见下 | 不记 |
| `session.backup` | 启动一个作业，见下 | 不记 |
| `session.restore` | 启动一个作业，见下。已经开着会话时不能跑 | 不记 |
| `template.save` | 把会话里的相册和收藏的结构存成一个模板，见下 | 不记 |

- **能不能跑**：每条命令照 A7a 的样子带判断。开着会话时 `open`、`new`、`restore` 不能跑；没开着时 `close`、`verify`、`backup`、`template.save` 不能跑。错误里要说清原因。
- **会话类的命令都不记历史步。**

**3. 校验是只读的。** `session.verify` 返回一份报告：每一条发现带严重程度、说的是什么、建议用哪条命令去修。查这些：数据库的完整性检查；有没有没有任何历史步引用、也不是任何照片当前快照的孤儿快照；有没有悬空的引用；游标有没有越界；照片表里的处理版本号和当前快照对不对得上；显示辅助参数那一格能不能解析；引用的外部文件还在不在（照片多的时候这一项是作业，见第 4 条，本波先支持数量少的情况，数量由你定一个上限并写明）。**校验全程不写库、不写文件**：对同一个会话校验前后，库文件的校验值相同（有日志文件时先合并再比）。

**4. 备份和恢复是作业。** 命令立刻返回一个作业标识；引擎自己收回作业的进度和完成，变成事件；能取消。

- `session.backup`：目标是自己的参数，已经存在且不是空的就拒绝。作业做的事：把日志合并进库，用在线备份接口拷库，拷 `Capture/`、`Selects/`、`Output/`、`Trash/` 四个文件夹；`Cache/` 不拷；有一个参数可以选不拷 `Trash/`。进度按已拷的字节或文件数报。**取消或者中途出错：把这个作业自己建出来的目标目录删掉**，报告里写明是被取消的还是失败的。备份的产物要能直接当成会话打开。
- `session.restore`：参数是备份在哪、恢复到哪。作业把备份整包拷回目标（库加四个文件夹，不拷 `Cache/`），然后按 `session.open` 的流程打开它。取消或出错同样清掉自己建出来的目标目录。
- 拷文件是 `lightamer-catalog` 里的函数：给它源、目标、进度回调和取消标记。引擎的源码里仍然不许出现文件操作。
- `session.open` 的失联扫描也是作业：打开立刻返回，扫描在外部文件的路径上做，标出已经不在的，进度经事件报。这一波库里的照片是导入那一波才有的，所以你用一个测试来证明它：测试自己往照片表里插几行（有的路径在，有的不在），然后打开，收回作业，看标记和事件对不对。

**5. 模板。** `template.save` 的参数是模板名。存的是相册和收藏的结构，不含任何照片。存到应用层的目录，默认是 `~/Library/Application Support/Lightamer/Templates/`；**这个位置可以用环境变量 `LIGHTAMER_APP_SUPPORT_DIR` 改**。测试一律把这个变量指到临时目录。**任何测试都不许写用户真实的应用支持目录。**

**6. 命令行。** 扩展 `lightamer-cli run --file`：

- 文件里的命令可以是会话类的。有 `session.new`、`session.open` 或 `session.restore` 的文件不许再带草稿会话的参数。
- 每执行完一行，把这个引擎里还没完的作业做完，把进度和完成事件打印出来，再执行下一行。这样一份文件从头跑到尾是确定的。
- 加一个参数 `--hold 秒数`：文件跑完之后不马上关会话，握着它等这么多秒再关。演示「双开被拒」要用它。
- 每一行打印的东西照现在的样子：是哪条、成功还是失败、原因。

**7. 前一半留下的两件事。**

- **持有人提示里的主机名是空的。** 它从环境变量或 `/etc/hostname` 里取，macOS 上两样都没有。改成向系统问主机名（本机实测要非空）。测试钉住。
- **显示辅助参数那一格写的时候不校验**，那是任务书定的原样存取。所以以后写它的命令要自己先校验。这一波没有写它的命令，你只需要在 `docs/SESSION.md` 里把这条写明白。

**8. 文档。** `docs/SESSION.md` 的后半：七条命令各做什么、参数是什么；备份和恢复的语义，取消之后留下什么；校验查什么、不做什么；作业的边界；命令行怎样用；持有人提示。`crates/README.md` 里引擎、会话库、命令行工具三行改成现在的内容。

**9. 给用户看的演示脚本。** `Scripts/rust-session-demo.sh`：在临时目录里把第一波做成的事从头演一遍，每一步打印结果，让人不看代码也知道做成了没有：

1. 新建一个会话，列出建出来的目录和文件。
2. 校验它：没有发现。
3. 往 `Capture/` 里放一个空的占位文件（不碰任何照片）。
4. 备份到另一个目录，列出备份里的内容，打开备份里的库确认完整。
5. 从备份恢复到第三个位置，打开恢复出来的会话，校验。
6. 双开被拒：后台起一个进程握着会话二十秒，前一个进程试着打开，打印被拒的信息和持有人；然后强杀后台那个，再打开一次，成功。
7. 把一个已有的文件夹当成会话打开，确认原来的文件没动。
8. 清掉临时目录。

脚本只用自己的临时目录和空的占位文件，不读用户照片库，不写真实的应用支持目录。跑完退出 0。
