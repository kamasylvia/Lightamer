## 要回答的问题

每个答案都要带证据：文件路径、行号、函数名、结构体字段。数字写出得出它的命令。

**Q1 历史存在哪里。** darktable 把一张图的编辑历史存在哪：XMP sidecar 文件，还是库数据库，还是两处都有。写清楚：文件放在哪（原图旁边还是集中目录）、什么时机写（首选项里的几种模式各是什么）、数据库里哪些表承载历史（表名、关键列）。一张图被两边都改过时，谁赢。先读 `src/common/xmp.c`、`src/common/history.c`、`src/common/image_cache.c` 一类文件，再顺着读。

**Q2 XMP 里有什么。** 把一张图的 XMP 中与编辑历史相关的全部条目列出来：模块顺序表、历史条目序列（每条的字段：模块名、模块版本、参数、多实例优先级与名字、混合参数、启用与否、蒙版相关条目）、历史末尾指针、各个哈希、XMP 版本号、RAW 参数。再列出非历史的条目：评分、色标、标签、标题与说明、作者、GPS。每项给名字、类型、所在代码位置。再列首选项里那些会影响渲染的全局项（比如高光重建策略、去马赛克方法）存在哪里，因为「观感一样」离不开它们。

**Q3 参数是怎么打包的。** 每个模块的参数怎样写进 XMP：是结构体内存直接序列化，还是逐字段位打包，还是两者都有。找出通用规则和判别方法，并用第 0 期会用到的模块各举一例：曝光、白平衡、曲线、裁剪、镜头校正、色彩输入与输出、显示变换用的色调映射模块、剪切。对每个例子给出：参数结构体定义的位置、字节大小、有没有位域、版本号函数、从旧版本迁移的函数。**写清一个 Rust 实现要做到哪几件事才能读出相同的值**：结构布局、对齐、字节序、版本迁移、模块顺序号。有没有模块用了指针或变长数据。

**Q4 模块顺序。** 模块顺序表怎样表示：顺序号的来源、用户自定义顺序怎么存、多实例怎么排。读 `src/common/iop_order.c`。给出默认顺序表的位置和版本号。

**Q5 多实例、混合与蒙版在历史里的表示。** 多实例靠什么区分。混合参数的结构和版本。蒙版：参数化蒙版、绘制蒙版、栅格蒙版各存在哪些条目里，参数结构在哪。第 0 期只要多实例和普通不透明度混合，其余标「后续」。

**Q6 不认识的东西怎么处理。** darktable 读到一条它不认识的模块的历史时做什么：跳过、丢弃、还是报错。读到不认识的 XMP 命名空间或条目时，写回时是保留还是丢掉。这决定 Lightamer 独有的功能能不能安全地存进同一份历史。给出代码位置。

**Q7 读写的入口函数。** 读和写各走哪些函数：从数据库或 XMP 装载历史、应用历史、把历史写回 XMP。列出调用链的关键函数，标出哪些依赖界面、哪些是纯逻辑。

**Q8 一份真实样例。** 在源码树里找一份带历史的 XMP 样例文件（测试目录、工具目录里通常有），把其中一条历史逐字节解释一遍：base64 解码后的每个字节对应参数结构体的哪个字段。找不到样例就说明没找到，改用代码里的默认值推演。
