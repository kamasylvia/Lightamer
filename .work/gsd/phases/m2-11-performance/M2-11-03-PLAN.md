> 两硬门均 OQ-2-A 签裁：①FULL 全渲染 warm <1s（可达性未知——带宽主导，>1s 走杠杆

> **零产线改码**（FULL 若 >1s：杠杆分解 = 计量与归因，不改渲染链——改码属新立项，
> 挂账 V2/Maintenance 交 M2-11-05 汇编）。

## 关键设计决策（planner 裁决，执行中不重开）

### KD-1 对标①FULL 桶全渲染 bench（新文件 FullRenderBenchmarkTests，IOP）

- **语义映射**（RESEARCH §B.1）：SpektraLab 45MP 全渲染 = 全分辨率印相出图 →
  我方 = CIRAW decode（warm，进程内二次）→ **FULL 桶全链**（M2 默认面 = Develop +
  1 Grade 默认 look + DRT SDR 尾段，M2-11-02 T1 同构造——依赖其 bench 形态复用）
  端到端渲一帧计时。
- **样张口径**：在库 60.2MP `input/RAW/DSC00012.ARW`（>45MP = 更严语义，径用）；
  100MP GFX 样张若有 tracked fixture 则加列，无则单列（60MP 为准，DECISIONS 注记
  更严口径）。`XCTSkipUnless` fixture 门；L009 SSD。
- **采读**：cold/warm 双档三轮中位；计时前 drain fence（L014）；`PERF|` print；
  分解探针伴随（decode 腿 / 主链腿 / 尾段腿分段计时——带宽归因输入，M2-10-02
  分解探针方法学同款）。
- **断言形态**（testPreviewFullChainFrameTime 先例）：`isReleaseBuild` 分叉——
  **Release 构建 assert warm < 1000ms（硬门本体）**；Debug 宿主只采读 + 宽松架构
  回归界（数字主导 = FULL 桶像素量 × GPU 带宽，Debug 失真不对门，m2-10 perf.md
  §A.3 双口径注记沿用）。Release 轮走 build-for-testing -configuration Release
  直启（M2-11-02 T5 同链路，重签惯例复用）。

### KD-2 对标②尾命中重渲计时（DrtTailTests 扩展，LAYERS）

- **语义映射**（RESEARCH §B.2）：SpektraLab 重印 0.01s（同配置数据热重贴）→ 我方
  = **尾平面缓存命中后的重渲腿**。两腿采读（preview-2560 桶）：
  ①**同参二次渲染**（全命中腿——`testSameRecordSecondRunIsAllHits` 场景加计时，
  stats.hits>0 && misses==0 前置断言保语义）；②**单参数 tick 尾段重放**
  （EOTF 切换或 DRT 参数 tick——`testEOTFSwitchReRunsOnlyTheTail` 场景加计时，
  misses==2/hits==1 前置断言）。
- **硬门 ≤10ms**：两腿中位均断言（命中腿预期亚毫秒~毫秒级，可达性高——OQ-2-A②
  原文）；Debug/Release 双栏采读，断言在 Release；Debug 记录 + 25ms 松界（防
  架构回归，非门）。前置命中断言失败 = 架构回归先红（语义门先行，计时门其次）。
- **计时纪律**：帧腿计时含 drain fence（L014）；PSO/缓存预热先行（warm 语义 =
  数据热平面在 `PipeCache`，与 SpektraLab「数据热」对齐——第一渲不计入）。

### KD-3 记录档与不对标注记

- preview 全链 warm（M2-11-02 T1 数字 + 在案 85ms）落 perf.md 记录档行 + 注记：

  腿（≤10ms 硬门），全链 warm 不参与对标」（§B.2 原文语义）。
- 二进制 32MB：perf.md 注记行（不对标；内置 AI 模型 ≈193MB by-design，
  `M2-10-01-SUMMARY.md:42` 锚）。

### KD-4 FULL >1s 时的杠杆分解（预案，OQ-2-A 触发线）

- 分解产物 = perf.md 归因表：decode 腿（warm 在案 0.11s 级）/ 主链腿（iop 趟数 ×
  FULL 带宽）/ 尾段腿（EOTF/format 转换）/ TilingPlan 窗口化在 FULL 桶实活
  （tile 粒度 × 并行度观测）——逐段数字 + 主导项判定。
- **裁决路径**：主导项为引擎级（带宽/趟数/窗口化不足）→ 硬门降为记录档 + 挂账
  V2/Maintenance（VALIDATION 注记，M2-11-05 汇编进挂账总清单）；主导项为意外
  缺陷（如尾平面在 FULL 桶漏缓存、格式转换冗余拷贝）→ 属真缺陷，报 orchestrator
  定修复归属（本 plan 仍不改码，修复走验收批 fix 或挂账）。**禁硬签必失败的门**。
