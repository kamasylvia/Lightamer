# Plan 03-05 — toneequal + guided filter（TilingPlan 首战）

## Goal

> 勘误：CONTEXT D-T3 写"5-band"，Darktable 实为 9 EV 带（noise..speculars）——按 dt 源码 9-band 实现，决策实质（全局多频段、无蒙版）不变。

交付 IOP-TONE-07（tone equalizer）——性能/架构上 Phase 3 唯一重模块（RESEARCH §4）。三段 Metal 图：luma mask 估计 → 细节保持滤波（EIGF/guided，`guided_filter.cl` 8 kernel MSL 直译 + EIGF exposure 权重）→ correction LUT 增益施加。**TilingPlan 首战在 FULL 管线**：100MP 下 luma mask + 滤波中间平面乘法爆内存（D-C1 3GB），分块 + overlap 正确性是本 plan 的架构验收。

**D-T3 语义（已定）**：toneequal = **全局多频段**（dt 默认模式，guidance 分解）——无蒙版依赖，Phase 6 补 per-region。Darktable 本体无 OpenCL（CPU only，`toneequal.c:313 TODO`），Metal 移植是自由发挥但**数学逐式对齐**。

**容差两档（RESEARCH Open#5 采纳 + Risk #7）**：golden 验收先锁 `details=none`（无滤波直通，1e-5 容差），EIGF 档（dt 默认）第二层 <1e-4 + ΔE<1.0（99% 分位）——CPU（dt）与 Metal 归约顺序不同，禁用 1e-5 硬闸卡死 EIGF。默认值与验收顺序解耦。

## Must-haves

- `CorrectionLUT.swift`（CPU）：9 个 EV 带参数 → 8 控制点 radial-basis（gaussian σ=√2）+ 三次样条插值 → 10001 点 LUT，clamp [0.25,4]；同一插值喂 UI 曲线图（CPU 代码一份两吃）
- luma mask kernel（9 估计器 + `linear_contrast` fulcrum=exp2(−4)）
- EIGF kernel 群：`guided_filter.cl` 8 kernel 直译 + `fast_guided_filter.h` EIGF 权重项；box mean O(1)/px（半径无关）
- golden 两档：none <1e-5 / EIGF <1e-4 + ΔE<1.0
- **TilingPlan FULL 首战**：overlap = max(radius,1)+halo 兑现；100MP 内存峰值 <3GB；逐 tile 输出与整幅一致
- PREVIEW 全链（含 toneequal）单帧 <16.6ms signpost 记录（PERF-5 预验，正式 CI 记录在 03-06）
