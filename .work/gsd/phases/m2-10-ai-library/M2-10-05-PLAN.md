## 关键设计决策（planner 裁决，执行中不重开）

### KD-1 帧协议（AIWorkerProtocol，Core 纯函数）

```swift
// 帧 = 4 字节大端长度 + JSON UTF-8；JSON envelope：
// 请求  {"id":N,"op":"open|run|ping|stop","profile":"…","units":"all|cpuAndGPU|cpuOnly",
//        "payload":{"tokens":[…],"mask":[…]} | {"jpegBase64":"…"} | {"inPath":"…","outPath":"…","tile":{…}}}
// 响应  {"id":N,"ok":true,"result":{"embedding":[…]} | {"outPath":"…"}} |
//       {"id":N,"ok":false,"error":"…","culpritUnits":"all"}   // culprit 回传 = 降级记账输入
```

- **上限纪律**：请求 JSON ≤ 8MB（KD 载荷分界）；超限 = 发送侧 typed 拒绝
  （构造期即拒——大图必须走路径通道）；响应 embedding（512×4B float 数组 JSON
  ≈ 11KB）恒小，无需二进制优化（DECISIONS 签注：v1 不做二进制 embedding 帧，
  834MB 档 jina 768 维亦 ~15KB）。
- **坏帧容忍**：长度前缀越界/UTF-8 解码失败 = worker 侧回 error 帧（连接保活）
  ——仅致命损坏（管道断裂）折叠为进程级 crash。
- **IPC 微基准 spike（OQ-10 定稿输入，T1 内执行）**：256² JPEG base64 过管道
  vs tmp 路径两条延迟各 50 次中位 + 50MP TIFF 路径通道往返延迟——数字入 SPIKE
  节（SUMMARY），只证通道分界合理，不改语义。

### KD-2 worker 进程体（AIWorkerMain）

- **分叉臂**：`LightamerEntryPoint.main` 增 `AIWorkerMain.runIfRequested()`——
  `CommandLine.arguments.contains("--ai-worker")` → 进入帧循环永不返回（`--mcp`
  臂 :61-77 同款：**永不构造 SwiftUI App**）；臂序 = flock fixture(DEBUG) →
  `--mcp` → **`--ai-worker`** → GUI。
- **会话缓存**：per `(profileID, units)` MLModel 缓存（Lumen `open` 会话缓存
  同型 :70-82）；`open` 首载计入 open 超时；`ping` 零载荷保活；`stop` → 清缓存
  优雅退出；SIGTERM → 退出码 0（删临时文件的守护语义——我们 tmp 文件由主进程
  管辖，worker 侧只清自己的 MLModel 编译缓存目录）。
- **crash 注入钩子（测试专用，DEBUG+env 双门）**：env
  `LIGHTAMER_TEST_AI_WORKER_CRASH=<profileID>` 命中 open 的 profile →
  `Darwin.exit(9)`（模拟原生崩溃——LUMEN_TEST_WORKER_CRASH :58/:73-75 同型）；
  **RELEASE 构建零此代码路径**（#if DEBUG + env 双门，测试可审计）。
- **错误面**：run 内异常 = error 帧回传不崩 worker（Lumen `'error'` 字符串
  同型）；MLModel 加载失败 = error 帧 + culprit=当前 units。

### KD-3 WorkerClient：generation 生命周期 + 降级链编排

```swift
// App——final class AIWorkerClient: AIInferencing, @unchecked Sendable（内部锁域）
//   spawn: Process(executableURL: Bundle.main.executableURL!, arguments: ["--ai-worker"])
//   generation: Int（每次重启 +1；会话缓存随代失效）
//   request(envelope, deadline) -> Response   // 1s 粒度轮询 + deadline（Lumen :188-199 同型）
//   超时 = kill() → WorkerCrashed("no response within N s")；死亡检测 = pipe EOF +
//   terminationStatus 非 0；管道异常统一折叠 AIWorkerCrashed
```

- **降级链（run/open 失败驱动，Lumen RemoteSession `_call` 重试循环 :266-282
  同型）**：尝试序 `[.all, .cpuAndGPU, .cpuOnly]`；crash（超时/死亡/exit 非 0）
  → culprit = 响应回传或崩溃前最后 `open` 的 units → `CompatRecord.record`
  （**CPU 崩不记**）→ 从序中剔除已禁 units 后重启（generation+1）续试；
  MAX_RETRIES=4 耗尽 → typed `.aiWorkerExhausted`（UI 呈现 = M2-10-07 设置页
  指引「重置 AI 兼容性记录」）。**open 900s / run 600s**（Lumen 常量平移——
  首用 CoreML kernel 编译在 open 预算内）。
- **AIInferencing conformer**：`embedText/embedImage` = open（缓存命中跳过）+
  run 组合；失败按降级链内部消化后重放——**消费方（02 引擎/03 registry）
  零改动**（缝语义；DECISIONS 签注切换面 = AIInferenceService 单点一行）。
- **功能降级不可用面**：spawn 失败（可执行缺席/权限）= typed `.workerUnavailable`
  直通消费方 → 搜索空态/任务失败呈现（**永不**回退 InProcess——OQ-5-A 字面）。

### KD-4 CompatRecord（Core，路径注入）

```swift
public struct CompatEntry: Codable, Sendable, Equatable {
    public var models: [String]        // 崩溃模型 profileID 集
    public var all: Bool               // 两不同模型同 units 崩 → true（该 units 全禁）
    public var last: LastCrash?        // {model, detail≤300, time}
}
// 结构：{ "<machineKey>": { "<units>": CompatEntry } }
// machineKey = sysctl hw.model + "/" + kern.osversion（OS build）
```

- `excluded(machineKey:model:) -> Set<AIComputeUnits>`：`all || model ∈ models`
  命中即排除（Lumen :119-121 同型）；`record(...)`：CPU 崩不记（:124-125 同型）
  + 锁内读改写 + tmp 同目录 rename 原子晋升 + 目录按需创建。
- **坏 JSON 容忍**：解析失败 = 视为空记录（下次记账覆盖重建——不崩主流程）；
  `resetAll()`（M2-10-07 重置按钮消费）= 删文件。

## 风险与边界

- **真子进程测试的宿主耦合**：测试宿主二进制 = test bundle 所宿主的可执行
  （test-direct.sh 直启宿主）——`Bundle.main.executableURL` 在测试进程内指向
  宿主，`--ai-worker` 臂在宿主内可用（App target 符号在宿主内；若宿主缺 App
  主二进制，改用 `xcrun` 定位构建产物路径注入——执行时定，DECISIONS 记录落点）。
- **MLModel 进程内编译缓存**：worker 侧 CoreML 编译缓存目录生命周期（清理时机）
  ——T1 实测定（`~/Library/Caches/LightamerModels/compiled/`），DECISIONS 签注。
- **超时杀进程的僵尸风险**：kill 后 `waitUntilExit` + 管道关闭序——测试钉无
