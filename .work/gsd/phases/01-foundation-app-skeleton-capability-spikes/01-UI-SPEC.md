# Phase 1 — UI Design Contract

> Visual and interaction contract for the Lightamer macOS-native RAW editor. This phase
> establishes the **design-system foundation** that all 13 phases inherit, plus the specific
> Phase 1 surfaces (three-column shell, empty state, top toolbar, menu bar, display-only
> editor viewport). Future phases (iop sliders, grid thumbnails, export dialog, yiyin panel)
> extend these tokens — do not invent new ones downstream.
>
> Generated by gsd-ui-researcher. Built against CONTEXT.md decisions D-07..D-13 (locked) and
> four researcher-resolved decisions: system-blue accent, SF Symbols only, English-source
> terse/technical copy, macOS-standard + C1/Lightroom keyboard scheme.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (Apple-native SwiftUI; no shadcn/radix — those are web) |
| Preset | not applicable |
| Component library | **Apple SwiftUI primitives only** (`NavigationSplitView`, `Table`, `Form`, `Inspector`, `.toolbar`, `.sidebar`, `ContentUnavailableView`, `Section`, `GroupBox`, `Toggle`, `Slider`, `Button`). No third-party UI libs (dependency-minimization lock). |
| Icon library | **SF Symbols** (`Image(systemName:)`) — single source of truth |
| Font | **System font** — `.font(.system)` / `Font.body` / `.title2` etc. Never hardcode SF Pro; the system resolves face + weight per locale. |
| Platform | macOS 27+ (SwiftUI on macOS 27 is the stability floor; `NavigationSplitView` production-stable since macOS 14) |
| Color scheme | **`.preferredColorScheme(.dark)` forced at the App root** — this is the D-10 lock. Tokens below are dark-mode-first. |
| Localization | **String Catalog** (`Resources/Localizable.xcstrings`); source = `en`; `zh` translated at parity; structure prepared for extension (SYS-05) |

### Layout Primitives

| Primitive | SwiftUI spelling | Phase 1 use |
|-----------|------------------|-------------|
| Three-column shell | `NavigationSplitView(three-column)` with `{ Sidebar } content: { Editor } detail: { Inspector }` | App root |

| Sheet/alert/toast | `.alert`, `.sheet`, custom toast overlay | Error display (D-26) |

### Corner Radii

| Token | Value | SwiftUI | Use |
|-------|-------|---------|-----|
| radius-sm | 4pt | `.cornerRadius(4)` or `RoundedRectangle(cornerRadius: 4)` | Inline chips, small controls |
| radius-md | 8pt | `.cornerRadius(8)` | Cards, inspector sections, buttons in group |
| radius-lg | 12pt | `.cornerRadius(12)` | Popovers, modal previews |
| radius-xl | 16pt | `.cornerRadius(16)` | Empty-state card, large surfaces |

(Apple HIG corner radii: macOS Sequoia uses ~8pt for controls, ~12pt for windows/sheets. `NavigationSplitView`'s sidebar inherits the system's vibrancy + corner treatment automatically — do not override.)

### Elevation / Shadow

macOS chrome uses **vibrancy** (`Material`) rather than drop shadows. Shadows are reserved for floating overlays (popovers, drag-previews, modals) and the empty-state card.

| Token | Value | SwiftUI | Use |
|-------|-------|---------|-----|
| elevation-0 | none | default | Sidebar / inspector / editor — flat with material backgrounds |
| elevation-1 | `Material.regularMaterial` | `.background(.regularMaterial)` | Toolbar, inspector body, sidebar |
| elevation-2 | `Material.thinMaterial` | `.background(.thinMaterial)` | Popovers, secondary surfaces |
| elevation-card | `.shadow(color: .black.opacity(0.25), radius: 12, x: 0, y: 8)` | `.shadow(...)` | Empty-state card, modals |

### Focus / Selection Rings

macOS draws focus rings automatically for keyboard-focused controls. **Do not disable** `.focusable()` indicators — they are the primary accessibility affordance. Selection (in sidebar/grid) uses `.accentColor` fill at `opacity(0.18)` (Apple's standard selection-tint strength).

## Spacing Scale

Declared values — **all multiples of 4** (8pt visual rhythm). Token names are advisory; the executor references them via the numeric values.

| Token | Value | SwiftUI | Usage |
|-------|-------|---------|-------|
| `xs` | **4pt** | `Spacer().frame(width: 4)` / `.padding(4)` | Icon-to-label gap, dense inline padding, slider-tick gaps |
| `sm` | **8pt** | `.padding(8)` | Compact control padding, toolbar item spacing, sidebar row insets |
| `md` | **12pt** | `.padding(12)` | Default control padding, inspector section horizontal inset |
| `lg` | **16pt** | `.padding(16)` | Default element spacing, inspector section vertical rhythm, sidebar vertical padding |
| `xl` | **24pt** | `.padding(24)` | Section padding, sheet content insets |
| `2xl` | **32pt** | `.padding(32)` | Layout gaps between major regions, empty-state card outer margin |
| `3xl` | **48pt** | `.padding(48)` | Empty-state interior spacing, hero iconography breathing room |
| `4xl` | **64pt** | `.padding(64)` | Page-level spacing (used sparingly in empty-state composition) |

**Exceptions:** none. The macOS toolbar follows system spacing (do not custom-pad `ToolbarItem`); `NavigationSplitView` column gutters are system-managed.

### Three-Column Layout Dimensions (Phase 1 specific — D-07, D-08)

| Column | Min | Ideal | Max | Collapse | Memory |
|--------|-----|-------|-----|----------|--------|
| **Sidebar** (left — Session nav) | 180pt | 240pt | 320pt | Yes — `NavigationSplitViewVisibility.doubleColumn` (hide sidebar) | Persist `sidebarWidth` via `@AppStorage("layout.sidebarWidth")` |
| **Editor** (center) | — | fills remaining | — | No (always present; only empty-state when no image) | n/a |
| **Inspector** (right — iop panels) | 240pt | 320pt | 460pt | Yes — `NavigationSplitViewVisibility.detailOnly` (hide inspector); toggle via toolbar `Sidebar Toggle` / `Inspector Toggle` | Persist `inspectorWidth` + `inspectorVisible` via `@AppStorage` |

SwiftUI spelling (Plan 01-01 already targets this):

```swift
NavigationSplitView(columnVisibility: $visibility) {
    SidebarView()
        .navigationSplitViewColumnWidth(min: 180, ideal: 240, max: 320)
} content: {
    EditorAreaView()
} detail: {
    InspectorView()
        .navigationSplitViewColumnWidth(min: 240, ideal: 320, max: 460)
}
.navigationSplitViewStyle(.balanced)
```

**Layout memory (D-08):** `@AppStorage` keys are prefixed `layout.*` and survive app relaunch. Window frame itself persists via the standard Scene `defaultSize` + `windowToolbarStyle`. The 上下左右栏互换 (C1-style full reorientation) is explicitly **deferred** (D-08).

## Typography

System font only. Type sizes follow Apple HIG macOS scale. `Dynamic Type` (see Accessibility) scales these for users who need larger text — never hardcode pixel sizes in pixels; always use the semantic `Font.*` token or a number the system scales.

| Role | Size | Weight | Line Height | SwiftUI | Phase 1 use |
|------|------|--------|-------------|---------|-------------|
| **Display** (hero) | 28pt | `.bold` | 1.15 | `.font(.system(size: 28, weight: .bold))` | Empty-state headline |
| **Title 2** | 22pt | `.bold` | 1.2 | `.font(.title2)` | Sheet titles (export dialog Phase 11 — reserved) |
| **Title 3** | 20pt | `.semibold` | 1.25 | `.font(.title3)` | Inspector section headers (Phase 3+ — reserved) |
| **Headline** | 17pt | `.semibold` | 1.3 | `.font(.headline)` | Sidebar selected row, toolbar button labels (when shown) |
| **Body** | 13pt | `.regular` | 1.45 | `.font(.body)` | Default text — empty-state body copy, inspector field values, metadata readouts |
| **Callout** | 12pt | `.regular` | 1.4 | `.font(.callout)` | Captions, secondary metadata |
| **Subheadline** | 11pt | `.regular` | 1.35 | `.font(.subheadline)` | Inspector labels ("Exposure", "Contrast"), thumbnail metadata overlays (grid Phase 9 — reserved) |
| **Footnote** | 10pt | `.regular` | 1.3 | `.font(.footnote)` | Status bar items, tooltips-adjacent hints, inspector small-print |
| **Caption 2** | 10pt | `.medium` | 1.25 | `.font(.caption2)` | Toolbar-only icon labels (on hover), toolbar overflow labels |
| **Mono** | 12pt | `.regular` | 1.4 | `.font(.system(size: 12, weight: .regular, design: .monospaced))` | EXIF numerical readouts (f/2.8, 1/200s, ISO 400) — Phase 9/12 reserved; Phase 1 status-bar FPS counter |

**Why system font:** SF Pro (and SF Pro SC for Chinese) ships with macOS, is automatically selected per locale, supports the full Dynamic Type range, and is the only font that renders correctly in vibrancy materials. Hardcoding any other font breaks localization (Chinese fallback) and accessibility scaling.

**Font design variant:** for code-like readouts (EXIF numerics, file paths, pixel dimensions), use `design: .monospaced`. This is the ONLY design variant permitted in Phase 1.

## Color

**Dark-mode-first.** All tokens defined as semantic colors that resolve to specific dark-mode RGB/HSB values. The spec mandates the dark values (because D-10 forces dark); the light-mode counterparts are documented for v2 (when D-10's toggle ships) but are NOT implemented in Phase 1.

Color is expressed as a SwiftUI `Color` extension in `Sources/UI/Theme/LightamerColors.swift`. Each token is implemented via `Color(nsColor:)` wrapping an asset-catalog color OR a direct `Color(red:green:blue:)` literal — executor picks one, but the **token names below are the contract**.

### Photo-Editor Neutral Chrome (the critical constraint)

The UI chrome (sidebar, toolbar, inspector, window background) **must be perceptually neutral gray**. This is non-negotiable for a photo editor: any color cast in the chrome biases the viewer's perception of the image's white balance. Reference: this is why Darktable, Capture One, and Lightroom all use neutral-gray chrome. Lightamer's neutrals are tuned to D50-ish gray (no warm/cool bias) at low luminance for dark mode.

### Neutral Scale (dark-mode values)

| Token | Dark hex | Dark HSB | Light hex (v2 only) | Use |
|-------|----------|----------|---------------------|-----|
| `neutral-0` (window bg) | `#0E0E10` | HSB(240, 6%, 6%) | `#F5F5F7` | Window background behind everything; the editor canvas surround |
| `neutral-1` (canvas bg) | `#161619` | HSB(240, 5%, 9%) | `#EBEBED` | Editor area background surrounding the photo (the "mat") |
| `neutral-2` (sidebar bg) | `#1E1E22` | HSB(250, 6%, 13%) | `#E5E5E8` | Sidebar / inspector panel background (with `.regularMaterial` vibrancy) |
| `neutral-3` (raised surface) | `#26262B` | HSB(255, 5%, 17%) | `#DCDCDF` | Inspector sections, toolbar surface, raised cards |
| `neutral-4` (control bg) | `#303035` | HSB(250, 4%, 21%) | `#D2D2D5` | Slider tracks, input field backgrounds, toggles (off state) |
| `neutral-5` (hover) | `#3A3A40` | HSB(255, 4%, 25%) | `#C7C7CB` | Hover states on rows / buttons |
| `neutral-6` (border) | `#3F3F45` | HSB(255, 4%, 27%) | `#BEBEBE` | Hairline borders between regions, dividers |
| `neutral-7` (border-strong) | `#4A4A52` | HSB(255, 5%, 32%) | `#A8A8AC` | Strong borders around the editor canvas (separates photo from mat) |

All neutrals are slightly blue-shifted (hue 240-255) to read as "cool gray" rather than warm — the conventional photo-editor chrome. Saturation is held to ≤6% so it's perceptually neutral, not "blue".

### Semantic Colors

| Role | Dark value | Token | Use |
|------|-----------|-------|-----|
| **Text primary** | `#ECECEE` (neutral-100 equiv) | `Color.lightamer.textPrimary` | Default text on dark surfaces — body copy, labels |
| **Text secondary** | `#9A9AA0` | `Color.lightamer.textSecondary` | Metadata captions, disabled-state labels, placeholder text |
| **Text tertiary** | `#6E6E76` | `Color.lightamer.textTertiary` | Disabled controls, "no value" readouts |
| **Text on accent** | `#FFFFFF` | `Color.lightamer.textOnAccent` | Text rendered on top of accent-color fills |
| **Background (window)** | `neutral-0` | `Color.lightamer.background` | Window root |
| **Background (canvas)** | `neutral-1` | `Color.lightamer.canvas` | Editor area surround |
| **Surface** | `neutral-2` / `neutral-3` | `Color.lightamer.surface` | Sidebar / inspector / toolbar |
| **Border** | `neutral-6` | `Color.lightamer.border` | Hairline separators |
| **Border strong** | `neutral-7` | `Color.lightamer.borderStrong` | Canvas edge |
| **Accent (selection/active)** | **System blue** — `Color.accentColor` | `Color.accentColor` | Active/selected/focused states, primary buttons, slider thumbs, checkbox-on |
| **Accent muted** | system blue @ `opacity(0.18)` | derived | Selected-row fill tint (sidebar, future grid) |
| **Danger (destructive)** | **System red** — `Color.red` | `Color.red` | Destructive actions only (delete session, discard edits); never decorative |
| **Warning** | **System orange** — `Color.orange` | `Color.orange` | Out-of-gamut warnings (Phase 13 soft-proof — reserved), unsaved-state indicator |
| **Success** | **System green** — `Color.green` | `Color.green` | Decode-complete confirmation, export success (Phase 11 — reserved) |

### Accent Discipline (60-30-10 rule applied)

| Role | % | Color |
|------|---|-------|
| Dominant (60%) | chrome backgrounds | `neutral-0` / `neutral-1` / `neutral-2` |
| Secondary (30%) | raised surfaces + text | `neutral-3` / `neutral-4` / text-primary |
| Accent (10%) | **system blue** | active row, focused slider thumb, primary CTA, selection |
| Destructive | <1% | **system red** — destructive buttons only |

**Accent reserved for:** active/selected sidebar row, focused control, primary toolbar CTA (when there is exactly one — e.g., "Open…" in empty state), slider thumb on focus, checkbox-on, link affordance. **Never** decorative — never paint the toolbar background blue, never color an inspector section header.

### MTKView Viewport Color

The `CAMetalLayer` backing `EditorMTKView` uses `pixelFormat = .bgra8Unorm` (Phase 1; `.rgba16Float` reserved for Phase 8 EDR). The layer's `backgroundColor` is `neutral-1` (the canvas mat). When no texture is bound, the viewport renders solid `neutral-1` — this is the "no image" state, distinct from the empty-state prompt (which replaces the whole EditorArea, not just the viewport).

## Interaction

### States (hover / press / focus / disabled / active)

| State | Visual | SwiftUI |
|-------|--------|---------|
| Default | token as defined | — |
| Hover | background → `neutral-5` (hover) for rows/buttons; accent-color opacity 0.08 for primary buttons | `.onHover { ... }` (system handles for standard controls) |
| Press | background → `neutral-6`; scale 0.98 (subtle) for icon buttons | `.buttonStyle(.plain)` + custom if needed; otherwise system |
| Focus | system focus ring (blue, 2pt) — never disable | automatic for keyboard-navigable controls |
| Disabled | opacity 0.4; no hover; cursor → default arrow | `.disabled(true)` |
| Active/selected (sidebar row) | background → accent @ 0.18; text → text-primary; leading 2pt accent bar | `List(selection:)` default |

### Transitions

### Focus Order

Logical reading order: **sidebar → toolbar → editor → inspector → status bar**. Within each region, focus follows the visual order (top-to-bottom, leading-to-trailing). `NavigationSplitView` manages column-level focus automatically; do not override `.focusTraversal()`.

`Tab` key moves between major regions; within a region, `Tab` follows visual order. `Shift+Tab` reverses. The MTKView editor is **focusable** (so keyboard shortcuts work when it has focus) but does not show a focus ring (it's a canvas, not a control) — set `.focusable(false)` if it would otherwise steal focus inappropriately.

### Dynamic Type

macOS Dynamic Type scales type for users who need larger text. **Mandatory:** use semantic `Font.*` tokens (`.body`, `.headline`, etc.) — never hardcode point sizes that bypass scaling. The system font scales automatically; the type scale above is the *baseline*, not a fixed ceiling.

For the empty-state Display headline (28pt), use `.font(.system(size: 28, weight: .bold))` wrapped in `.dynamicTypeSize(...DynamicTypeSize.accessibility3)` clamping if the composition would overflow at maximum size — but generally let it scale.

### Reduced Transparency
