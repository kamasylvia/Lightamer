# Plan 04 — IOPModule + V50Order + Layer skeleton (D-03a) + PixelPipe + PassthroughModule: no-op pixelpipe runs through EditorMTKView

## Goal

Land the **iop contract**, the **module-order table**, the **Layer abstraction skeleton** (D-03a — the L005 countermeasure), and a **layer-aware no-op pixelpipe** that proves the chain end-to-end. Specifically: (1) `protocol IOPModule` + supporting types (`IOPFlags`, `IOPColorspace`, `IOPiece`, `IOPBufferDesc`, `ROI`) in `LightamerCore/Sources/Pipe/` (all `public`); (2) `enum V50Order` in `LightamerCore/Sources/Foundation/` porting Darktable's `iop_order.c:298-415` verbatim (`public`); (3) the **Layer skeleton** in `LightamerCore/Sources/Layers/` — `protocol Layer`, `struct LayerStack`, `enum LayerKind`, `enum BlendMode`, a concrete `BackgroundLayer` (all `public` per D-03a — types visible cross-module from day one so Phase 2's pixelpipe is layer-aware without rewrite); (4) `PixelPipe` skeleton (`internal` to Core) that traverses the base layer's chain only (Phase 1 scope) and is layer-ready for Phase 6; (5) the full `PassthroughModule: IOPModule` in `LightamerIOP/Sources/` (refactoring Plan 03's minimal `Passthrough.swift`); (6) `EditorState` constructs a `LayerStack(baseLayer:)` on decode and runs the no-op pixelpipe.

This plan completes success criterion #3: "a no-op pixelpipe chain (single pass-through piece) runs without error through the `EditorMTKView` bridge." The decoded RAW now flows through `RAWDecoder` → `PixelPipe` (base layer, single pass-through piece) → `EditorMTKView`. The Layer skeleton (D-03a) ensures Phase 6 fills implementation without architectural rewrite (L005).

## Tracer vertebra mapping

Wave 1 plan #4. Completes the pixelpipe half of the vertebra. After Plans 01-04: File → Open → decode → `LayerStack(baseLayer:)` constructed → `PixelPipe` traverses the base layer's `[PassthroughModule]` → output texture → `EditorMTKView`. The vertebra is fully wired.
