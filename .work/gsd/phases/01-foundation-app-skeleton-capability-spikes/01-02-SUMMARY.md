## Deviations from plan (with reasons)

1. **RAW UTI literals corrected to the real macOS 27 identifiers.** The
   plan's literals (`public.canon-cr3`, `com.sony.raw-image`,
   `com.panasonic.rw2-image`, `public.adobe-dng`) don't match what the OS
   actually declares. Verified via `UTType(tag:tagClass:)` on this machine:
   `com.canon.cr2/cr3-raw-image`, `com.sony.arw-raw-image`,
   `com.panasonic.rw2-raw-image`, `com.adobe.raw-image`,
   `com.leica.rwl-raw-image`, `com.hasselblad.3fr-raw-image`,
   `com.phaseone.raw-image`, etc. `rawUTIs` contains the verified set plus
   the plan/research spellings as aliases, and routing additionally accepts
   any UTI conforming to `public.camera-raw-image`. All plan-required
   strings remain grepable in the set.
2. **RAW 9 gate uses `CIRAWDecoderVersion.version9` (the modern class), not
   `kCIInputDecoderVersionKey`/`RawDecoders`.** The macOS 27 SDK ships the
   new typed `CIRAWFilter` class (failable `init(imageURL:)`,
   `supportedDecoderVersions: [CIRAWDecoderVersion]`, readwrite
   `decoderVersion`, `semanticSegmentationSkyMatte`) — the deprecated
   option-key API is `API_TO_BE_DEPRECATED`. Same semantics as D-22.
3. **blackLevel/whiteLevel have no CIRAW key in this SDK.** Sourced from the
   ImageIO DNG dictionary (`kCGImagePropertyDNGBlackLevel/WhiteLevel`,
   native sensor domain — Phase 2 `rawprepare` input) when present;
   normalized defaults (0.0/1.0) otherwise. Baseline exposure +
   neutral chromaticity come from the queryable `CIRAWFilter` properties.
4. **RAW-path smoke test + RAW fixtures deferred to Plan 06** (execution
   protocol: never fabricate fake `.CR3`s; no real camera RAW samples exist
   on this machine). The RAW branch is compile-verified and UTI-verified;
   the corrupt-file smoke exercised the typed-error path end-to-end. The
   `.v9` stamp assertion likewise waits for a RAW-9-supported camera sample.
5. **Two extra app files touched beyond `files_modified`:**
   `ContentView.swift` and `EditorAreaView.swift` needed `decoder`
   parameters (and `import LightamerCore`) because they are the other two
   `EditorState.load` call sites (toolbar Open, empty-state drop). Plan 04's
   EditorState stub signature change made this unavoidable; `EmptyStateView`
   itself is unchanged (closure captured the new call).
6. **XMP not walked in Phase 1.** The macOS 27 SDK property dictionary
   carries no `kCGImagePropertyXMPDictionary`; XMP reading goes through the
   `CGImageMetadata` APIs and is reserved for Phase 12 (META-04). IPTC is
   walked as the capture-time fallback; RAW-06's Phase 1 fields are all
   EXIF/TIFF/GPS-sourced.
7. **Cancellation entry-point added in a follow-up commit (4baa194):** the
   raster branch is synchronous, so without a `Task.checkCancellation()` at
   `decode()` entry a cancelled raster decode would still complete. Caught
   by the cancellation smoke test.
8. **`.work/plans/01-02/smoke.swift` retained** as the durable record of the smoke
   verification (per the process-files-in-`.work` convention); it is not a
   build target.
